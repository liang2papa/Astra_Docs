# 공통 스킬·보스 소환기 연결

2026-10-26 C++ 반영 기준. **아래는 사용자 Editor 연결안이며 에셋 적용·Blueprint/StateTree Compile·PIE 완료 기록이 아니다.** GA·Task·DA·몽타주 에셋 이름/경로는 아직 확정하지 않았다. 정책과 코드 책임은 [스킬](../03_시스템%20설계/스킬.md) 참조.

2026-10-28 사용자 빌드 오류 C2248 후속: BeginCombatAttack의 NPC형 포인터에서 protected override GetEntityDataAsset을 호출하던 실수 수정. 기존 AEntityCharacter의 public 가상 조회 경로로 호출하고 실제 NPC override 반환은 유지. 이 조회는 Entity DA.AutomaticSkillInterval을 읽으며 GA 조회가 아니다. GA는 캐릭터 BP.StartupAbilityClasses에서 기존 Entity ASC에 부여하고 Skill Task→Mediator가 태그로 활성화한다. 호출부 정적 대조까지, 수정 후 빌드·PIE 미수행.

## 연결 순서

1. Editor 종료 후 `Astra_SoulLinkEditor / Win64 / Development` 전체 빌드, Editor 완전 재시작. 새 UCLASS·태그·enum이 있으므로 Hot Reload로 대체하지 않음.
2. 보스 BP에 `EntitySkillComponent` 추가. 기존 Entity 초기화가 Context.SkillComp와 사망 구독을 연결하므로 BP에서 별도 Init/Tick 호출하지 않음.
3. 소환 DA, 소환 GA, Upper Skill Task/State, ABP 스킬 몽타주 매핑을 아래대로 연결.
4. 보스 BP의 `StartupAbilityClasses`에 소환 GA 한 개 부여. **이 배열은 Entity DA가 아니라 캐릭터 BP 클래스 기본값 소유.** 보스 Entity DA의 Skills에는 소환 DA 등록.
5. 수동 RequestSkill로 한 시전부터 확인한 뒤 Entity DA의 자동 선택 간격/가중치를 켜서 일반 유탄→소환 순서를 확인.

좀비 BP/ABP/Controller/근접 StateTree는 기존 사용자 연결본 사용. 좀비에 SkillComponent를 추가할 필요 없음. 소환된 좀비 BP의 Auto Possess AI는 `Placed in World or Spawned`, AI Controller Class·Entity DA·Enemy Faction·Base/Upper 트리·근접 GA는 기존 좀비 설정을 사용한다.

## 소환 DA

Data Asset 생성 클래스 `EntitySummonSkillDataAsset`.

| 프로퍼티 | 연결/조건 |
|---|---|
| SkillId | 이 캐릭터에서 고유한 Name. ABP SkillMontages의 Key와 일치. 이름 미정 |
| AbilityTag | `Ability.Skill.Summon`. GA Asset Tags와 정확히 일치 |
| UseType | 2026-10-28 추가. 공통 Instant/Channeling 분류, 기존 간격형 소환은 기본 Channeling 유지 |
| Duration | 채널링 초. 0보다 크게 사용자 지정 |
| ExecutionClass | 기본 `EntitySummonSkillExecution` 유지 |
| Locks Movement / Requires Montage | 소환 DA 기본 true 유지 |
| SummonClass | 완성한 좀비 캐릭터 BP 클래스 |
| SpawnCount | **한 시전의 수량**. 1 이상. 살아 있는 좀비 총수 제한 아님 |
| SpawnInterval | 두 번째부터의 생성 간격. 수량 2 이상이면 0보다 크게 지정 |
| InnerRadius / SpawnRadius | 시전자 주변 제외 반경 / 바깥 반경(cm). 0 ≤ InnerRadius < SpawnRadius |
| PlacementAttempts | 한 개체를 놓을 위치의 최대 시도 횟수. 1 이상 사용자 지정 |
| NavigationProjectionExtent | NavMesh 투영 및 바닥 탐색 범위(cm). X/Y/Z 모두 양수 사용자 지정 |
| FloorOffset | 바닥 위 캡슐 배치 여유(cm). 0 이상. 기본 0 |

첫 생성은 BeginRequestedSkill 성공 시각 `0초`. 이후 `SpawnInterval`, `2×SpawnInterval` 순서. 반드시 `(SpawnCount−1)×SpawnInterval ≤ Duration`. 마지막 생성까지 끝나도 채널링은 Duration까지 유지한다. 미정 수치는 0으로 비워 두었으므로 필수 값을 입력하기 전에는 실행이 거부된다.

일반 스킬·영혼 결속의 사용 형식은 공통 UseType 필드로 지정한다. 공통 Instant는 Duration=0, Channeling은 Duration>0. 사용 형식과 효과 종류·비용 방식은 다른 데이터다. 이번 변경으로 GA/Task 연결을 추가할 필요는 없으며 기존 소환 DA의 UseType 기본값 Channeling과 Duration 양수를 빌드/재시작 후 확인한다. 새 C++ enum/UPROPERTY이므로 UHT 포함 전체 빌드가 필요하다.

소환 위치는 소환 클래스의 Nav Agent 기준 도달 가능한 NavMesh·걸을 수 있는 바닥을 찾고, 해당 클래스의 캡슐이 겹치면 다른 위치로 재시도한다. 시전자 및 다른 Entity 위를 바닥으로 사용하지 않는다. 시도 소진은 시전 Failed, 그 전에 생성된 개체는 유지. NavMesh 없는 공중/벽 내부 강제 생성 없음. Zombie의 실제 초기화·AI 가동은 기존 BP/캐릭터 초기화 경로를 사용한다.

## Entity DA와 자동 선택

| 위치 | 설정 |
|---|---|
| 보스 BP → StartupAbilityClasses | 소환 GA 한 개 추가. 동일 AbilityTag에 매칭되는 다른 GA 중복 부여 금지 |
| 보스 Entity DA → Skills[n].Skill | 원본 소환 DA 참조. 런타임 임의 DA를 등록 없이 요청하면 거부 |
| Skills[n].AutomaticWeight | 양수면 자동 선택 후보, 0이면 제외. 한 종류만 켜면 그 종류 선택 |
| AutomaticSkillInterval | NPC 자동 선택 간격(초). 0이면 자동 선택 없음. 값 미정 |

첫 전투 Attack 진입부터 간격 계산. 시간이 되어도 일반 무기 공격이 한 번 성공했고, 해당 무기 실행과 `State.Combat.Attacking` GA가 **모두 끝난 뒤** 선택한다. 선택/요청 후 다음 간격은 그 시점부터 계산하며, 또 다른 일반 공격 성공 없이 스킬끼리 연달아 실행하지 않는다. 유탄이 착탄할 때까지 기다리는 조건은 아니다.

이 선택 정책은 기존 NPCAIController 소유, 채널링/생성은 SkillComponent·Execution 소유. Brain에 새 Skill enum이나 별도 Tick·타이머를 만들지 않는다. 기존 Brain Attack/Chase Task는 유지. 스킬 종료 후 현재 Brain 의도로 이동을 재요청한다. 공격 범위 밖이면 현재 Chase 흐름으로 복귀하며 과거 이동 목적지를 억지로 복원하지 않는다.

## ABP·몽타주

보스 ABP 클래스 기본값 `Action Animations → Skill Montages`에 원소 추가. Key=소환 DA SkillId, Value=보스 Skeleton의 소환 채널링 Montage. 기존 선정 모션은 Revenent Idle이며 최종 리타게팅/에셋 생성 완료를 뜻하지 않는다.

```text
보스 기본 Locomotion Pose
→ 기존 FullBody Slot (채널링 Montage와 동일한 Group/Slot)
→ Output Pose
```

채널링 Montage는 Duration 동안 유지되어야 한다. 클립이 짧다면 Montage Sections의 해당 Section 다음 Section을 자신에게 연결해 반복한다. 예: Default → Default. 컴포넌트가 Duration 종료에 해당 몽타주만 BlendOut으로 정지한다. Duration 전에 Montage가 정상 종료하거나 다른 몽타주로 중단돼도 Failed 처리. 근접 `Melee_Hit`나 총기 `Weapon_FireCommit` Notify는 소환용으로 넣지 않는다. 생성 시각은 소환 DA 소유다.

## 소환 GA

부모 클래스 `AstraEntityGameplayAbilityBase`. 기존 Weapon GA를 상속하지 않는다. 기본 InstancedPerActor 유지, 시전 중 재활성화는 허용하지 않는다.

| 설정 | 값 |
|---|---|
| Asset Tags | `Ability.Skill.Summon` |
| Activation Owned Tags | `State.Skill.Casting` |
| Activation Blocked Tags | `State.Dead`, `State.Stunned`, `State.Combat.Attacking`, `State.Combat.Reloading`, `State.Skill.Casting` |
| Cost / Cooldown | 이번 보스 스킬은 미지정. 비용 GE 등을 임의 추가하지 않음 |

GA 변수: SkillComp(EntitySkillComponent 참조), ExecutionId(Guid), AbilityTag(GameplayTag), bAwaitingResult(Boolean=false). 이 변수들은 해당 GA 인스턴스 소유. Avatar Actor는 실제 실행 Entity이며 GetPlayerCharacter로 다시 찾지 않는다.

```text
Event ActivateAbility
→ Get Avatar Actor From Actor Info → Cast EntityCharacter
→ Get EntityContext → SkillComp
→ IsValid(SkillComp) + HasSkillRequest
  ├─ false → CancelAbility
  └─ true
     → ExecutionId = SkillComp.GetExecutionId
     → AbilityTag = SkillComp.GetRequestedSkill.AbilityTag
     → bAwaitingResult = true
     → Bind Event to SkillComp.OnSkillFinished (OnThisSkillFinished)
     → CommitAbility
       ├─ false → CancelAbility (OnEndAbility가 해당 요청 정리)
       └─ true → SkillComp.BeginRequestedSkill(ExecutionId, AbilityTag)
          ├─ true → 대기 (여기서 EndAbility 하지 않음)
          └─ false
             → bAwaitingResult인 경우만 CancelAbility
                (Begin 내부 실패가 이미 종료 이벤트를 보냈으면 중복 종료하지 않음)

OnThisSkillFinished(FinishedId, SkillId, Result)
→ FinishedId == ExecutionId AND bAwaitingResult
  ├─ false → 아무 작업 없음
  └─ true
     → bAwaitingResult = false
     → Unbind Event from OnSkillFinished (이 GA의 OnThisSkillFinished만)
     → Result == Completed
       ├─ true → EndAbility
       └─ false → CancelAbility

Event OnEndAbility(bWasCancelled)
→ bAwaitingResult = false
→ IsValid(SkillComp)
  └─ true
     → Unbind Event from OnSkillFinished (같은 Event만, Unbind All 금지)
     → SkillComp.CancelSkill(저장한 ExecutionId)
→ SkillComp 참조 해제
```

CommitAbility 전에는 실제 소환을 시작하지 않는다. OnEndAbility는 정상/실패/외부 취소 모두 실행되며, 이미 완료한 ID에 대한 CancelSkill은 무시된다. 새 요청의 현재 ID를 다시 가져와 취소하면 안 된다. 채널링 시계·소환 반복·몽타주 재생은 C++에서 이미 하므로 GA의 Delay/Timer/Tick/PlayMontage를 중복 추가하지 않는다.

## Upper Skill Task

새 Blueprint Task는 기존 `00_STT_EntityBase`를 상속해 부모의 `AEntityCharacter`·`EntityContext` 바인딩 재사용. 별도 GetPlayerCharacter/Controller 캐스팅/Context 재생성 없음. 새 Task의 최종 이름/경로는 미정.

Task 변수: ExecutionId(Guid), AbilityTag(GameplayTag), bAbilityStarted(Boolean=false). Context의 참조만 사용하며 자동 선택 타이머나 스킬 수치는 Task에 복사하지 않는다. **Should State Change on Reselect=true**로 이전 실행 정리/새 ID 진입을 구분한다.

```text
EnterState
→ bAbilityStarted = false
→ EntityContext.SkillComp 유효 + HasSkillRequest
  ├─ false → FinishTask(false)
  └─ true
     → ExecutionId = SkillComp.GetExecutionId
     → AbilityTag = SkillComp.GetRequestedSkill.AbilityTag
     → PublishUpperState
        Target=EntityContext.StateEventBus
        StateEvent=SkillEntered, Source=AEntityCharacter
     → EntityContext.StateMediator.TryActivateAbilityByTag(AbilityTag)
     → Branch(ReturnValue에 연결)
       ├─ false → SkillComp.CancelSkill(ExecutionId) → FinishTask(false)
       └─ true → bAbilityStarted = true → Running

Tick
→ bAbilityStarted이면 SkillComp.GetLastResult(저장 ExecutionId)
  ├─ None → Running
  └─ Completed/Failed/Cancelled
     → EntityContext.AbilitySystem.HasMatchingGameplayTag(State.Skill.Casting)
       ├─ true → Running (GA 종료 정리 대기)
       └─ false
          → bAbilityStarted = false
          → FinishTask(Result == Completed)

ExitState
→ bAbilityStarted이면
   → 먼저 bAbilityStarted = false
   → EntityContext.StateMediator.CancelAbilityByTag(저장 AbilityTag)
→ SkillComp 유효하면 CancelSkill(저장 ExecutionId)
```

Enter에서 ID/태그를 **GA 활성화 전 저장**한다. GA가 같은 호출 안에서 실패/종료할 수도 있기 때문. Tick은 결과 감지이며 재활성화가 아니다. 완료 결과를 받은 후 즉시 Finish하지 않고 Casting 태그 해제까지 기다린다. Exit는 다음 요청의 ID를 조회하지 않고 저장한 ID만 취소한다.

## Upper StateTree 전이

기존 Upper Command 이벤트 구조를 사용한다. 에셋의 실제 노드를 편집한 것은 아니므로 아래 조건을 사용자 트리에 추가한다.

```text
Root / 명령 수신 공통 부모
→ On Event: StateTree.Event.UpperCommand
→ Event Payload: FUpperStateCommandPayload.Command == Skill
→ Skill 상태 (위 Skill Task)
   ├─ Task Succeeded → 기존 Ready
   ├─ Task Failed → 기존 Ready (실패도 정상 무기 흐름으로 복귀)
   ├─ CancelAction / ForceHolster → 기존 취소·수납 목적지 (Exit에서 해당 스킬 취소)
   └─ Disable / Death → 기존 비활성·사망 흐름 (Death Critical 유지)
```

가능하면 기존 Upper Command Condition의 Command enum만 Skill로 지정한다. Skill 전이는 Ready를 포함한 사용 가능한 무기 상태의 공통 부모에서 수신한다. 같은 Skill 상태로 새 명령이 오면 재선택 진입이 가능해야 하며, 매 Tick Skill 재진입 전이는 만들지 않는다. Native에서 요청 전 현재 무기/GA 완료를 검사한다.

SkillEntered 사건은 Mediator가 Lower Stop·예약 AutoReload 취소로 중계한다. 실제 채널링 중 이동 잠금은 소환 DA/SkillComponent가 소유한다. 기존 Base의 Lower Stop 명령 수신→Ground/정지 연결을 유지한다. Brain Attack의 종료를 Skill 상태 진입의 선행 조건으로 만들거나 Brain Task에서 스킬 GA를 또 활성화하지 않는다.

## 정상·실패·취소 수명

```text
일반 유탄 성공·GA 종료 → 간격 도달/가중 선택
→ RequestSkill(등록된 DA, 현재 Target, 실행 Entity)
→ Upper Skill 명령 → Skill Task → Mediator → 소환 GA
→ CommitAbility → BeginRequestedSkill
→ 이동 잠금·채널링 Montage → 즉시 첫 좀비
→ 간격별 다음 좀비 → Duration 종료
→ 해당 시전 실행/몽타주/이동 잠금 정리 → OnSkillFinished(Completed)
→ GA EndAbility → Casting 해제 → Task 성공 → Ready
→ 현재 Brain의 공격/추격/순찰 선택

GA 활성화 거부 / Commit 실패 / 외부 취소
→ 저장 ID CancelSkill → Cancelled → GA/Task 종료
→ 앞으로 생성할 좀비 중단, 이미 생성된 좀비 유지

NavMesh·배치 실패 / 필수 Montage 누락·중단·조기 종료
→ Failed → GA 취소 → Task 실패 → Ready
→ 이미 생성된 좀비 유지

시전자 HP 0 / Actor EndPlay
→ 현재 시전 취소 + 해당 시전자가 앞선 모든 시전에 소환한 좀비 제거
→ 다른 시전자 소환물 유지
```

보스 제거는 좀비에 처치 피해/Death GA/보상을 요청하지 않고 Actor를 제거한다. 정상 전투 중 좀비 처치·드롭 정책은 기존 경로 소유. 살아 있는 좀비 총수에는 상한이 없다. 일반 피격 취소 여부는 기존 Entity DA 정책을 따르며 보스의 행동 중단 비허용 설정을 유지한다.

## 로그와 플레이 확인

```text
astra.Debug Skill.Execution 1
astra.Debug NPC.Combat 1
astra.Debug off
```

Skill 로그: Caster·Execution(Guid)·SkillId·Event·Spawned. `Requested → Started → Summoned… → Completed`가 정상. Requested만 있으면 Upper 명령 수신/Task/GA·태그 연결 확인. Started 후 실패면 함께 출력된 필수 Montage/NavMesh/배치 오류 확인. Failed/Cancelled는 다음 Summoned가 없어야 한다. 콘솔 등록/로그 형식은 기존 Utils/Debug 서브시스템 한곳에서 관리한다.

| 플레이 조건 | 기대 결과 |
|---|---|
| 수동 RequestSkill(보스 Context.SkillComp, 등록 DA) | GA 진입 후 즉시 1개, 이후 DA 간격·수량. 등록하지 않은 DA는 거부 |
| 마지막 생성=Duration 경계 / 프레임 지연 | 예정 수량 누락 없음, 생성 종료 후에도 Duration까지 채널링 유지 |
