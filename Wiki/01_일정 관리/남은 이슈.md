# 남은 이슈

> 최종 갱신: 2026-09-02
> 목적: 임시 처리되었거나 검증이 남은 문제만 추적한다. 완료된 항목은 [해결된 이슈](%ED%95%B4%EA%B2%B0%EB%90%9C%20%EC%9D%B4%EC%8A%88.md)로 이동한다.

## 애니메이션 잔여 작업

### ANIM-004. Draw/Holster와 Pistol Idle 포즈 호환성

- Blend In/Out `0.2초 + Exponential In`으로 임시 완화했다.
- 호환 애니메이션 세트를 확보한 뒤 다시 조정해야 한다.

### ANIM-005. 권총 Equip 시 손가락 관통

- 양손 그립은 대체로 맞지만 오른손 손가락 일부가 왼손을 관통한다.
- 애니메이션 교체 또는 Control Rig의 손가락 보정이 필요하다.

### ANIM-006. 무기 종류별 Animation Layer 확장

- 현재는 권총 기준 `ABP_Unarmed`에 직접 구성되어 있다.
- Rifle 등으로 확장할 때 Weapon Animation Layer Interface와 무기별 Linked Anim Layer 전환을 적용한다.

## 로코모션 잔여 작업

### LOC-001. Vault 전용 애니메이션 부재

- 1/4 호 이동 로직은 구현되었으나 점프 기반 표현이 부자연스럽다.
- 전용 Vault 애니메이션 또는 루트모션/모션워핑에 적합한 애셋 확보 전까지 임시 보류한다.

### LOC-002. Hanging 손·무릎 깊이 보정

- 손 높이는 조정되었지만 벽 깊이와 무릎 관통은 애니메이션·벽 간격에 따라 남을 수 있다.
- `HangingWallClearance`를 게임플레이 판정값으로 과도하게 보정하지 않고 애니메이션/IK에서 해결하는 방향을 유지한다.

### LOC-003. LedgeHanging→Fall Loop Inertialization 경고 재발 확인

- 에디터 종료 또는 Hanging 이탈 시 Inertialization 노드 경고가 보고된 적이 있다.
- 현재 AnimGraph 변경 후 재발 여부를 회귀 테스트한다.

## 무기·전투 잔여 작업

### WPN-002. Fire/Reload 취소와 상태 충돌 회귀 테스트

- Sprint, Evade, Jump, Hanging, 피격, 사망 시 Fire/Reload/Draw/Holster가 올바르게 취소되는지 검증한다.
- 발사 종료 후 자동으로 Sprint로 복귀하면 안 된다.

### WPN-003. 연사·반동·HUD 피드백

- 발사 확정 시 반동 누적, `PlayerCameraManager` 적용, Fire Montage 종료 후 회복 코드는 반영되었다.
- 단발 Commit과 Continuous 공격 Tick 성공 시 반동이 누적되며, 실패한 공격 요청은 반동을 만들지 않는다.
- 무기별 DataAsset에 반동 범위·최대치·`RecoilRecoveryDuration`을 설정하고 빌드 및 PIE에서 체감과 회복을 검증해야 한다. 기본 회복 시간은 0이므로 미설정 시 즉시 복구된다.
- 이동 사격은 조준점 확산·탄도 오차, 정지 사격은 카메라 반동을 중심으로 분리한다.
- 조준·이동·외부 보정·내구도를 반영한 명중률과 확산 계산 함수는 구현됐지만 실제 `ShotDirection`과 HUD 조준점에는 아직 연결하지 않았다.
- 공중 조준 `80`, 공중 미조준 `0` 데이터는 확정·추가됐지만 현재 명중률 함수는 이동 속도만 검사하므로 Airborne 우선 분기가 아직 필요하다.
- HUD Crosshair의 상태·반동 기반 Scale 갱신 C++는 구현됐지만 실제 명중률과 거리별 확산 반경에는 아직 연결하지 않았다.
- 카메라 조작은 반동 회복을 막지 않으며, 회복 중 새 발사가 성공하면 남은 반동에 새 반동을 누적한 뒤 회복을 다시 시작한다.

### WPN-010. 지속 공격 종료와 Effect 수명 회귀 검증

- `AttackInstanceId`를 유지하며 Continuous Tick과 Beam Effect Start/Update/Stop이 같은 공격에 연결되는지 확인한다.
- 입력 해제뿐 아니라 탄약 부족, Holster, Unequip, Stun, Death와 Ability Cancel에서도 동일한 종료 경로를 타야 한다.

### WPN-011. RapidFire 반복 발사

- 현재 일반 총기 발사는 `SingleShot`만 완성되어 있고 `RapidFire`는 enum과 데이터만 존재한다.
- 입력 유지, AttackCooldown 이후 다음 발사 요청, 입력 해제 중지와 빈 탄창 Reload 전환을 구현해야 한다.
- Sprint, Evade, Jump 취소와 Aim Hold 중 연발 유지, 발사별 탄약·반동·HUD 갱신을 검증한다.

### WPN-004. 총구 화염·사운드 동시 재생 제한

- Muzzle VFX와 Fire Sound를 Anim Notify 또는 발사 확정 시점에 연결한다.
- 동시 발사음이 과도하게 겹치지 않도록 Sound Concurrency를 설정한다.

### WPN-005. Aim Hold/Toggle과 카메라 확대

- 무기 옵션에 따라 Hold는 짧은 확대, Toggle은 큰 확대를 지원해야 한다.
- Aim 입력, 카메라 FOV, 자동 수납 타이머 초기화, Sprint 해제를 하나의 흐름으로 검증한다.

### WPN-006. HUD 탄약 표시

- HUD Widget·DataAsset·Component와 PlayerController 이벤트 중계 C++ 기반은 적용·빌드되었다.
- Widget Blueprint 레이아웃과 `DisplayAmmo` 연결은 별도 HUD 작업에서 완료해야 한다.
- WeaponInstance의 등록 탄수와 InventoryComponent의 Available 탄약을 원본으로 사용하는 C++ 경계는 구현됐다.
- Widget Blueprint에서 현재 탄수·Available 탄약 표시와 Preferred/Reserved 표현을 연결해야 한다.

### WPN-007. Projectile 충돌 피드백

- 표면별 분기는 보류하되 기본 충돌 VFX와 Sound는 `ProjectileDataAsset`에서 지정할 수 있게 한다.

## 아이템·인벤토리 잔여 작업

### ITEM-001. 최신 C++ 전체 빌드와 PIE 회귀 검증

- ItemInstance·Inventory·Gear·ItemTransfer·WorldItem Factory·Inventory Menu 코드는 Editor에 반영됐다.
- 헤더와 Reflection 변경을 포함한 Development Editor / Win64 전체 빌드의 최종 UBT `Result:`를 확인해야 한다.
- Inventory Stack·Capacity, Gear Equip·Swap, Split·Drop·Pool, Reservation·Reload와 Pawn 교체 후 상태 유지 경로를 PIE에서 검증한다.

### ITEM-002. WorldItem 부분 획득 검증과 상호작용 전환

- `AWorldItemActor`는 여러 ItemInstance를 보관하고 Pawn Overlap 시 수용 가능한 수량만 Inventory·Gear로 이전한다.
- 일부만 획득하면 남은 수량과 Actor를 유지하고, 모두 소진되면 `OnDepleted` 후 Factory Pool로 반환되는 경로를 PIE에서 확인한다.
- 현재 Overlap 즉시 획득을 향후 별도 Interaction 입력 방식으로 교체한다.
- ItemDataAsset의 Soft ItemStaticMesh 자동 로딩과 취소 정책은 아직 연결하지 않았다.

### ITEM-003. Bag Capacity 감소 Transaction

- Bag은 일반 Auto Equip과 Inventory↔Gear 이동에서 현재 제외된다.
- Compact 후 새 Capacity 밖 Item과 해제 Bag을 하나의 WorldItemActor로 옮기고, 실패 시 원상 복구하는 Transaction을 구현한다.

### ITEM-004. SaveData와 레벨 전환 복원

- ItemInstance UObject와 Runtime Item ID를 직접 저장하지 않고 별도 SaveData Schema를 구현한다.
- 새 World의 ItemInstanceFactorySubsystem을 통해 Instance와 ID를 재발급한 뒤 Inventory·Gear를 복원한다.
- Preferred Ammo Map도 현재 Transient이므로 Player SaveData에 포함해야 한다.

### ITEM-005. Inventory·Gear UI

- PlayerController 소유 `UInventoryMenuComponent`, `UInventoryMenuWidget`, Toggle Input과 Equip·Unequip·Split·Drop 요청 C++ API는 구현됐다.
- 7×7 Inventory/Gear Slot, 아이콘과 Inventory/Gear Context Menu가 Blueprint에 연결됐고 장비 해제는 동작 확인됐다.
- 장착 슬롯 선택 Menu와 `RequestEquipItem`, Stack 분할 Dialog와 `RequestSplitStack`, Drop 결과를 최종 연결·검증한다.
- Tooltip, 실패 메시지, Locked Capacity와 메뉴 열기·닫기 회귀 검증을 완료한다.
- Preferred/Reserved 탄약은 Stack 독립 설계를 유지하며 대표 Stack·아이콘·수량 표현을 확정한다.

## 구조·GAS 잔여 작업

### ARCH-001. EntityStatusModel 단계적 이전

- 상태·스탯 중 GAS Attribute/Tag가 소유해야 할 항목과 StateTree 입력 컨텍스트가 소유할 항목을 분리한다.
- NPC도 동일한 ASC/AttributeSet 기반을 사용할 수 있도록 PlayerState 전용 소유로 고정하지 않는다.

### ARCH-002. AbilitySet + 입력 태그 기반 부여 구조

- PlayerCharacter의 기능별 Ability 직접 참조를 줄이고 AbilitySet과 GameplayTag 기반 활성화로 이관한다.

### ARCH-003. NPC용 ASC 소유 위치 확정

- 빙의·변신·일반 NPC 모두 재사용할 수 있도록 Pawn/PlayerState 중 실제 싱글플레이 요구에 맞는 소유 위치를 확정한다.

### ARCH-004. Soul-Link Ability 구현

- `Possession`, `DirectSkill`, `Transform`, `Totem`은 설계만 정리된 상태다.
- 플레이어 무기 어빌리티와 아스트라 어빌리티 셋이 섞이지 않도록 태그와 부여/회수 규칙을 구현해야 한다.

## 다음 작업 권장 순서

1. 장착 슬롯 선택과 Stack 분할 Dialog의 최종 요청 경로를 연결한다.
2. Inventory/Gear Drop과 WorldItem Pool 재사용·실패 경로를 PIE에서 확인한다.
3. 최신 Item·Inventory·WorldItem·Menu 소스를 전체 빌드하고 Pawn 교체까지 회귀 검증한다.
4. Bag Capacity 감소와 초과 WorldItem Transaction을 구현한다.
5. SaveData Schema와 레벨 전환 복원을 구현한다.
6. Preferred/Reserved 탄약 UI를 연결한 뒤 RapidFire·명중률 작업으로 돌아간다.
