# 2026-08-13 일일 개발 리포트

## 오늘의 목표

- GAS의 Ability·Attribute·ASC 소유권을 변신과 빙의까지 고려하여 확정
- Base/Upper StateTree 간 직접 결합을 제거할 상태 중재 구조 설계
- 플레이어 입력, PlayerController, StateTree, GAS의 실행 흐름 정리
- 권총 Fire Ability를 확장할 GameplayTag와 Blueprint 기반 GA 구조 준비

## 완료한 작업

### 1. GAS 적용 범위 검토

- Unreal GAS 공식 문서, Lyra AttributeSet 구조와 Atomic Heart 적용 사례를 검토함.
- GAS는 StateTree를 대체하지 않으며, StateTree가 행동을 선택하고 GAS가 행동의 비용·쿨다운·실행·취소를 담당하도록 확정함.
- `EntityStatusModel`의 동적 전투 데이터는 장기적으로 AttributeSet과 GameplayTag로 이동시키되, 로코모션 상태 선택은 StateTree가 계속 담당하도록 정리함.
- 상태 데이터가 커진 뒤 이전하지 않고 초기 단계에서 PlayerState/ASC/Attribute 구조를 도입하기로 결정함.

### 2. 변신·빙의·Ability 소유권 설계

- 변신 중에는 기존 플레이어 무기를 사용할 수 없도록 함.
- 변신 해제 후에도 스킬 쿨다운이 유지되어야 하므로 플레이어의 장기 ASC와 AttributeSet은 PlayerState가 소유하도록 설계함.
- 빙의 시 입력의 주체는 PlayerController로 유지하고 Avatar/Pawn만 교체되는 Unreal의 Possession 구조를 사용하기로 함.
- 아스트라 NPC도 공통 Entity AttributeSet을 사용할 수 있으나 PlayerState가 아닌 NPC 자신 또는 NPC 전용 지속 객체가 ASC를 소유하도록 구분함.
- 현재 게임은 싱글플레이를 기준으로 구현하고 서버 권한·복제는 추후 확장 항목으로 남김.
- 아스트라 Ability 구성은 일반 공격, 소울링크 스킬 1개, 일반 스킬 1~2개를 기본으로 함.

### 3. Gameplay Ability 계층 정리

- 다음 Ability 계층을 기준 구조로 확정함.

```text
GA_AstraBase
├─ GA_WeaponBase
│  ├─ GA_WeaponFire
│  ├─ GA_WeaponReload
│  └─ GA_WeaponAim
├─ GA_SoulLinkBase
│  ├─ Possession
│  ├─ DirectSkill
│  ├─ Transform
│  └─ Totem
├─ GA_AstraActionBase
│  ├─ Astra Basic Attack
│  ├─ Astra Skill 1
│  └─ Astra Skill 2
└─ GA_CommonBase
```

- 구체 Gameplay Ability는 가능하면 Blueprint로 생성하고 C++는 공통 기반과 안전 검사만 제공하도록 원칙을 확정함.
- C++로 작성하던 구체 Weapon GA를 Blueprint 기반으로 전환하는 방향을 정함.
- GA Weapon Base에서 Current Avatar를 기준으로 WeaponComponent를 찾아 캐싱하는 `ResolveWeaponComponent` 구조를 설계함.
- Avatar가 변경되면 캐시를 갱신하고, 동일 Avatar에서는 매 활성화마다 Component를 다시 찾지 않도록 함.

### 4. PlayerController와 입력 라우팅

- PlayerController는 로컬 플레이어 입력을 받아 현재 Possess한 Pawn/Avatar에 전달하는 주체로 정리함.
- 입력값 자체를 StateTree가 영구 소유하지 않고 Controller 또는 입력 Context가 입력 의도를 기록하고 StateTree가 이를 소비하도록 함.
- 빙의로 Pawn이 바뀌어도 동일한 PlayerController가 새 Avatar에 입력을 전달할 수 있도록 설계함.
- Fire, Reload, Aim 입력은 GameplayTag 기반 Intent/Event로 Upper StateTree에 전달하는 방향을 확정함.
- Ability 입력과 상태 이벤트를 구분하여, StateTree 진입 이벤트 게시와 GAS Ability 활성화 요청이 서로 다른 역할임을 정리함.

### 5. Upper StateTree 통합 설계

- WeaponCarryState와 UpperAction은 강한 선후 관계를 가지므로 하나의 Upper StateTree로 통합하는 방향을 채택함.
- Upper 상태는 `Holstered`, `Drawing`, `Ready`, `Holstering`, `Fire`, `Reload`, `Aim`으로 구성하기로 함.
- 무기를 들고 있어야 Fire/Reload/Aim으로 진입할 수 있고, 수납 상태의 입력은 Drawing 완료 후 예약 행동으로 연결함.
- 조준은 무기 옵션에 따라 Hold와 Toggle 방식을 모두 지원하며, 두 방식의 카메라 확대량을 다르게 설정할 수 있도록 설계함.
- STC는 빠른 사전 전이 검사, GA는 실제 실행 직전의 최종 안전 검사를 담당하도록 함.
- STT는 상태 진입 이벤트를 게시하고 Mediator를 통해 해당 Gameplay Ability를 활성화하도록 함.

### 6. EntityStateMediator 설계

- 하위 컴포넌트와 StateTree가 서로를 직접 참조하지 않도록 `EntityStateMediatorComponent`를 상태 이벤트 허브로 두기로 함.
- Base StateTree와 Upper StateTree는 GameplayTag 이벤트만 게시하고, Mediator가 반대 StateTree와 GAS에 취소·전이 명령을 전달하도록 함.
- Upper Fire/Aim/Reload 진입 시 Sprint를 취소하고, Base의 Sprint/Airborne/Traversal 진입 시 Upper 행동을 취소하거나 무기를 강제 수납하도록 정책을 정리함.
- 피해, 기절, 사망은 Damage/Health 계층이 이벤트를 게시하고 Mediator가 StateTree와 Ability 취소를 중재하도록 함.
- PlayerCharacter는 상태 세부 판단을 소유하지 않고 Component 조립, 입력 전달, Context 제공을 중심으로 하는 Shell 역할을 유지함.
- Unreal 계층에서는 GameMode가 씬 규칙인 기존 Director와 유사하며, 개별 Entity의 하위 객체 생성과 정책 조립은 Entity Mediator가 담당할 수 있음을 정리함.

### 7. Blueprint 우선 원칙 및 기반 준비

- Blueprint에서 생성·연결 가능한 StateTree, Condition, Task, Gameplay Ability는 Blueprint를 우선 사용함.
- C++ Component 자동 생성은 초기 단계의 임시 구성으로 허용하되 추후 Blueprint 조립으로 이전할 수 있도록 함.
- Input, Ability, State, Event 계열 GameplayTag의 기초 분류를 추가함.
- `EntityStateEventBus`, `EntityStateMediatorComponent`, Entity/Player Context를 사용하는 상태 전달 기반을 준비함.
- STC와 STT의 입력은 개별 WeaponComponent, StatusModel, LocomotionComponent를 반복 바인딩하지 않고 `Actor + EntityContext`를 기준으로 단순화하기로 함.

## 확정한 설계

- PlayerState는 플레이어가 Pawn을 교체해도 유지되어야 하는 ASC, AttributeSet, 쿨다운과 장기 자원을 소유함.
- NPC는 PlayerState를 사용하지 않지만 동일한 Entity AttributeSet과 GAS 규칙을 사용할 수 있음.
- PlayerController는 입력 주체, StateTree는 행동 선택, GAS는 행동 실행, Mediator는 상태 간 충돌 조정, WeaponComponent는 무기 도메인 실행을 담당함.
- StateTree 간 직접 참조와 하위 Component 간 직접 통신을 피하고 GameplayTag Event와 Mediator를 사용함.
- 구체 GA는 Blueprint 우선, 공통 데이터형·Component·안전장치는 C++ 우선으로 작성함.
