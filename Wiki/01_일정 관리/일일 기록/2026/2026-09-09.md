# 2026-09-09 일일 개발 리포트

> 집계 시간: 2026-09-09 09:00 ~ 2026-09-10 09:00

## 오늘의 목표

- 로드맵 기준 다음 작업 순서 확인
- WeaponComponent의 책임 분할안 설계
- 원본 프로젝트 적용 전 검토용 전체 코드와 적용 안내 준비

## 완료한 작업

### 1. 남은 이슈와 작업 순서 검토

- 로드맵과 남은 이슈를 대조해 `ARCH-005 WeaponComponent 분할`을 다음 우선 작업으로 확인함.
- 이후 순서를 EntityLocomotionComponent 분할, EntityStatusModel 제거, 무기 선택, NPC 구현 순으로 정리함.
- 재장착 후 발사 불가 문제는 리팩터링 전후 회귀를 구분할 수 있도록 무기 선택 구현 전에 원인 분석하는 방향을 제안함.

### 2. WeaponComponent 분할 검토안 작성

- WeaponComponent는 외부 API를 제공하는 Facade·중재자로 유지하고 기능별 실행을 Handler로 분리하는 구조를 설계함.
- 외부 객체 참조는 `WeaponRuntimeContext`, 기능별 실행 상태는 `WeaponRuntimeState`로 분리함.
- Carry, Aim, Fire, Reload, Recoil, Attack의 6개 Handler로 책임을 구분함.
- PlayerCharacter의 공격 실행 처리를 WeaponComponent 내부의 Fire·Attack 경로로 이동하는 안을 작성함.
- PhysicalProjectile, Hitscan, Beam 전달 방식을 Attack Handler가 처리하도록 통합함.
- 기존 외부 이벤트 이름은 호환을 위해 유지하되 공격 실행 요청이 아닌 결과 알림으로 역할을 정리함.

### 3. 검토 패키지와 적용 안내 작성

- 원본 Astra_Unreal 프로젝트를 직접 수정하지 않고 교체 파일, 전체 코드 전문, 적용 안내와 검증 자료를 별도 패키지로 구성함.
- 기존 WeaponComponent 메서드 101개 유지 여부와 Handler 이동 메서드 70개를 정적으로 대조함.
- 첨부 Blueprint 호출 노드 22개와 직접 상태 변수 접근 1개를 확인함.
- `BP_PlayerCharacter`의 직접 `WeaponCarryState` 접근을 `GetWeaponCarryState()` 호출로 바꿔야 하는 지점을 정리함.
- 정적 검사에서 원본 소스 해시가 변경되지 않았고 최종 오류 0개임을 확인함.

## 확정한 설계

- WeaponComponent는 Facade·명령 중재 역할을 유지함.
- 외부 참조와 런타임 실행 상태를 별도 구조체로 분리함.
- PlayerCharacter는 무기 공격 실행을 담당하지 않고 명령과 결과 소비에 집중함.
- 공격 실행은 `Fire Handler → WeaponComponent CommitAttack → Attack Handler` 경로로 처리함.
- GA와 StateTree의 종료 계약 변경은 이번 범위에서 제외함.

## 테스트·검토 결과

- 검토 패키지 20개 파일의 정적 감사를 완료함.
- 기존 메서드 101개, 이동 메서드 70개와 Blueprint 호출 노드 22개를 대조함.
- 원본 Astra_Unreal 소스는 변경하지 않음.
- UE 빌드, UHT, Blueprint Compile과 PIE는 수행하지 않았으므로 실제 통합 검증이 필요함.

## 잔여 이슈

- 검토 패키지를 Astra_Unreal에 적용한 뒤 컴파일 오류 조정.
- `BP_PlayerCharacter`의 직접 Carry State 변수 접근 교체.
- Draw·Fire·Reload·Holster Montage Notify와 Montage Instance ID 검증.
- 정상·실패·취소·무기 교체 경로 PIE 회귀 테스트.
