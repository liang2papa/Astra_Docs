# 2026-08-21 일일 개발 리포트

> 집계 시간: 2026-08-21 09:00 ~ 2026-08-22 09:00

## 오늘의 목표

- 권총 조준·사격·재장전 기본 동작 최종 점검
- 수납 상태 Aim 및 Aim 중 Fire StateTree 구조 수정
- WeaponComponent의 캐릭터 의존성을 줄이는 차기 공격 처리 구조 설계
- 일일 기록 문서를 GitHub 웹에서도 탐색할 수 있도록 링크 형식 개선

## 완료한 작업

### 1. 무기 Gameplay Ability 태그 복구

- `GA_WeaponAim`, `GA_WeaponFire`, `GA_WeaponReload`의 Ability Tag와 Activation Owned Tag를 재확인함.
- 세 Ability 모두 `Activation Required Tags`는 사용하지 않는 구성이었음을 확정함.
- Aim은 Reloading, Fire는 Reloading, Reload는 Attacking과 Aiming 상태에서 차단하도록 기본 차단 태그를 정리함.
- Aim 상태가 Fire를 차단하지 않도록 구성함.

### 2. 수납 상태 Aim → Draw → Aim 흐름 수정

- 수납 상태에서 Aim 입력 시 Pending Action만 저장하고 Draw 이벤트를 보내지 않아 동작이 멈추던 원인을 확인함.
- `RequestWeaponAimStarted()`가 수납 상태에서 `RequestWeaponDraw(EPendingWeaponAction::Aim)`을 호출하도록 수정 방향을 정리함.
- `UWeaponComponent::RequestWeaponDraw()`가 Pending Aim 저장과 `Event.Weapon.RequestDraw` 전송을 함께 수행하는 흐름을 확인함.
- C++ 수정 후에도 동작하지 않던 원인이 `ST_UpperState`의 `Holstered → Drawing` 전이에 `Event.Weapon.RequestDraw`가 없었기 때문임을 확인함.
- Blueprint의 중복 `Request Weapon Draw`와 `Set Pending Weapon Action` 호출을 제거하고 입력 함수 한 곳에서 처리하도록 정리함.

### 3. Aim 부모 State와 Aim Fire 구성

- `Aim`을 부모 State로 두고 `Aim Ready`, `Aim Fire`를 자식 State로 구성함.
- 부모 `Aim`에는 `STT_WeaponAim`, `Aim Fire`에는 `STT_WeaponFire`만 배치하도록 함.
- `Aim Ready → Aim Fire`는 `Input.Ability.Primary`, `Aim Fire → Aim Ready`는 `On State Completed`로 전이하도록 정리함.
- `STT_WeaponAim`의 Ability 활성화 성공 경로에서 `Finish Task`를 호출하지 않아 Aim 부모 State가 유지되도록 함.
- `STT_WeaponAim`이 두 곳에 중복 배치되어 두 번째 Task가 이미 활성화된 Aim Ability를 실패로 처리하던 문제를 찾아 제거함.
- 수정 후 조준 중 Fire Montage, `Weapon_FireCommit`, Fire 완료 및 Aim 상태 복귀가 정상 실행되는 것을 확인함.

### 4. 권총 핵심 기능 1차 완료 점검

- Draw/Holster, 자동 Holster, Pending Fire/Reload/Aim 동작을 점검함.
- Fire, Reload, Aim의 StateTree·GAS 연결과 Commit Notify 기반 탄약 처리를 점검함.
- 빈 탄창 공격의 Reload 전환, Hold/Toggle Aim, 수납 상태 Aim, Sprint 중 Aim 진입 흐름을 확인함.
- 무기별 Aim FOV와 PlayerCameraManager의 FOV 보간을 확인함.
- Aim Offset, 왼손 FABRIK, 발사 중 Pitch 유지 등 현재 애니메이션 연결 상태를 점검함.
- 권총의 조준·단발 사격·재장전·Draw/Holster 기본 기능을 1차 완료 상태로 판단함.

### 5. Aim 중 Reload 및 후속 기능 검토

- Aim 부모 State에 `Input.Ability.Reload → Reload` 전이를 두어 Aim 종료, GA 취소, FOV 복귀 후 Reload로 진입하도록 함.
- 발사·충돌 효과음과 VFX는 실행 코드만 있고 실제 에셋 연결은 폴리싱 단계로 남겨 둠.
- 반동 요청 데이터와 이벤트는 존재하지만 PlayerCameraManager의 실제 카메라 반동 적용은 미구현 상태임을 확인함.
- HUD는 Pawn 교체 후에도 유지되는 PlayerController가 `UPlayerHUDComponent`를 소유하고 현재 Pawn의 WeaponComponent만 다시 연결하는 구조를 제안함.

### 6. Cast와 의존성 구조 검토

- `ACharacter*`를 `APawn*`으로 사용하는 `Cast<APawn>`은 상속에 따른 자동 업캐스팅이 가능하므로 불필요함을 확인함.
- `IAbilitySystemInterface` 캐스팅은 구체 Player 클래스 의존이 아닌 인터페이스 의존이므로 허용 가능한 형태로 구분함.
- PlayerState가 소유한 ASC를 `FindComponentByClass`로 찾는 방식은 현재 구조와 맞지 않음을 확인함.
- 상속 관계와 Component 소유 관계를 구분하고 `GetOwner()`는 부모 객체를 별도로 반환하는 것이 아니라 실제 소유 Actor 인스턴스를 `AActor*` 타입으로 반환함을 정리함.
- Projectile의 Owner와 Instigator가 각각 논리적 소유 관계와 공격을 유발한 Pawn을 나타낸다는 차이를 정리함.

### 7. WeaponComponent 차기 리팩터링 설계

- WeaponComponent가 `OwnerCharacter`, Controller, CharacterMovement 또는 PlayerCharacter의 구체 타입을 알지 않도록 방향을 확정함.
- PlayerCharacter는 WeaponComponent 이벤트를 받아 탄약 소유 객체와 공격 실행 객체에 명령을 분배하는 중앙 중재자 역할을 담당하도록 함.
- WeaponComponent는 발사 가능 여부, 조준 결과, 피해량, 탄약 비용, 반동 및 공격 확정 데이터 생성까지만 담당하도록 함.
- 발사 확정 이벤트를 `OnWeaponAttackCommitted`로 정의하고 PlayerCharacter가 탄약 감소와 공격 전달을 분배하도록 설계함.
- 현재에는 WeaponComponent에 탄약 감소를 요청하고, Inventory 도입 후에는 같은 위치에서 InventoryComponent에 탄약 아이템 소비를 요청하도록 확장 경계를 정함.
- Projectile Actor 생성과 Object Pool은 물리 발사체 전용 `ProjectileFactory`가 담당하도록 함.

### 8. 공격 전달 방식과 탄약 데이터 설계

- `PhysicalProjectile`, `Hitscan`, `Beam`을 공격 전달 방식으로 분리함.
- ProjectileFactory는 실제 Actor가 필요한 PhysicalProjectile에만 사용하도록 함.
- Hitscan은 즉시 Trace, Beam은 지속 Trace와 Niagara 표현을 사용하는 방향으로 정리함.
- 공격 전달 방식과 시간적 발사 방식은 서로 다른 축으로 분리함.
- 발사 방식은 SingleShot, RapidFire, ThreeShot, ChargedShot, Continuous 조합을 고려하도록 함.
- 탄약 비용을 코드에 1로 고정하지 않고 WeaponDataAsset에서 관리하도록 함.
- 단발 소비량, 지속 소비량, 시간 경과에 따른 소비량·피해량 증가 규칙을 무기 데이터로 정의하는 방향을 확정함.
- Ranged 무기는 권총·소총·유탄발사기 모두 카메라 목표 방향을 사용하고, Melee만 Aim Solution 계산에서 제외하도록 함.
- 평시 Aim Solution 갱신은 기존 PlayerCharacter Blueprint Tick에서 수행하고, 발사 직전에는 다시 계산하도록 설계함.

### 9. 문서와 개발 환경 정리

- 일일 기록 인덱스와 8월 11일~20일 리포트의 Obsidian Wiki Link를 GitHub 호환 상대 Markdown 링크로 변환함.
- 일일 기록 폴더에 남은 Wiki Link가 없고 상대 링크 대상이 모두 존재함을 확인함.
- UE 5.8 개발의 주 IDE는 Visual Studio 2026, VS Code는 보조 편집기로 사용하는 구성을 정리함.
- 프로젝트 NTFS 권한에는 명시적 DENY가 없고 사용자·Authenticated Users의 수정 권한과 폴더 상속이 정상임을 확인함.
- 빌드 로그에도 실제 Access Denied가 없었으며, `apply deny-read ACLs` 오류는 프로젝트 ACL이 아니라 Codex 샌드박스의 중첩 쓰기 루트 적용 충돌로 판단함.
- 현재 세션에서는 빌드를 권한 승인 방식으로 실행해야 하며 실제 프로젝트 빌드 검증은 수행하지 않음.

### 10. 객체별 설계 문서 정리

- Entity, Player, Item, Prop의 정의와 책임을 각각 독립 설계 문서로 분리함.
- Entity와 Prop의 경계, Item과 월드 표현 Actor의 경계, Player 전용 정책과 Humanoid 공용 행동의 경계를 정리함.
- PlayerCharacter의 중앙 중재 역할과 WeaponComponent의 사용 주체 비의존 원칙을 문서화함.
- 공격 확정 이벤트를 `OnWeaponAttackCommitted`로 통일하고 PhysicalProjectile·Hitscan·Beam 실행 책임을 무기 시스템 문서에 반영함.
- `Consumable`과 `Crafting`은 Item 종류가 아니라 중복 가능한 속성이라는 기준을 객체 설계 문서에도 반영함.

## 확정한 설계

- Aim은 부모 State, Aim 중 Fire는 자식 `Aim Fire` State에서 실행함.
- 수납 상태 Aim은 `RequestWeaponDraw(Aim)`을 통해 Draw 이벤트와 Pending Action을 함께 처리함.
- WeaponComponent는 사용 주체의 구체 Actor 타입과 Projectile 생성 방식을 알지 않음.
- PlayerCharacter는 WeaponComponent와 탄약·공격 실행 객체 사이의 중앙 중재자 역할을 담당함.
- `OnWeaponAttackCommitted`는 탄약 소비와 공격 실행에 필요한 확정 데이터를 전달함.
- ProjectileFactory는 PhysicalProjectile Actor 생성과 Pool 관리에만 사용함.
- DeliveryType과 ShootType을 분리하고 탄약 소비 규칙은 WeaponDataAsset이 소유함.
- 일일 기록 링크는 GitHub와 일반 Markdown 뷰어에서 동작하는 상대 경로를 사용함.
- Entity, Player, Item, Prop은 객체별 설계 문서를 두고 기획 분류와 구현 책임을 상호 연결함.
- 공통 공격 확정 이벤트 이름은 `OnWeaponAttackCommitted`를 사용함.
