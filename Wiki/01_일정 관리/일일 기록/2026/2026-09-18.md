# 2026-09-18 일일 개발 리포트

## 오늘의 목표

- 무기 조준 침라 FOV 제어를 GA 기반으로 정리
- 공격(발사) 경로 PIE 검증과 미동작 원인 수정

## 완료한 작업

### 1. 조준 FOV 제어 기반 반영

- `UAstraWeaponGameplayAbilityBase`에 `GetEntityContext`, `GetWeaponComponent` 추가 — Avatar의 EntityContext를 캐시해 lazy 재해석
- `StartAimCameraFOV`, `StopAimCameraFOV`가 이 getter를 사용하도록 교체
- 에임 FOV 정상 작동 확인 (09-17 기반의 PIE 검증 포함)

### 2. 공격 미발사 원인 2개 확정 및 수정

- **원인 1 — GA 자기 태그 차단**: `FireEquippedWeapon`의 `CanFireWeapon()`이 `State.Combat.Attacking` 태그를 검사하는데, 이 태그는 GA 자신의 ActivationOwnedTags라 ActivateAbility 시작 전에 이미 부착됨 → 항상 false. 조건 판정은 STC가 담당하므로 `FireEquippedWeapon`에서 CanFireWeapon 체크 제거
- **원인 2 — 중복 return**: `StartFireMontage`에 `}return false;`가 중복으로 남아 몽타주 분기가 무조건 false를 반환하던 코드 복구
- 진단 로그 7개 추가 → 원인 확정 후 전부 제거

### 3. 발사체 방향 폐백 추가

- ProjectileActor는 기존에 `ShotDirection` 기반 발사 — 오늘 변경은 **ShotDirection이 0벡터일 때 `GetActorForwardVector()`로 폐백**
- 0벡터 시 `GetSafeNormal()`이 0을 반환해 Velocity=0으로 활성화되어 발사체가 정지하던 간헐 현상 방어

### 4. 연발 입력 릴리즈 처리 추가

- `ProcessBufferedWeaponInputs()`에서 `IsInputHeld(Input.Attack)` 해제 감지 → `RequestWeaponFireCompleted()` 호출
- 연발 시 버튼을 떼도 계속 발사되던 문제 수정

### 5. 연발 중 에임 추적 수정 (이중 잠금 해소)

- 플레이어 틱의 에임 갱신이 `!IsFireInProgress()` 조건으로 연발 중엔 멈추던 문제 → 조건 제거
- `CommitInitialShot`이 첫 발 고정값(Locked)만 쓰던 것을 `LatestFireAimSolution` 우선 사용으로 변경
- 연발 중 시점 이동 시 총알이 새 에임 방향으로 나감

### 6. 자동 재장전 설계 확정 및 기반 추가

- 설계: 공격 시 탄약 부족 → AttackTask는 종료, Ready가 요청 보관, STC_CanReload가 요청을 보고 Reload 상태로 전이 (트리 안에서 처리, GA 직접 호출 없음)
- WeaponComp에 `RequestAutoReload()` / `IsAutoReloadRequested()` / `ConsumeAutoReloadRequest()` 추가, 무기 해제 시 초기화

### 7. 플레이테스트 (PIE 디버깅 세션)

- Lev_테스트전용 레벨에서 PIE 반복 수행 — 공격 미발사 추적을 위한 진단 로그 세션
- STC/GA WeaponComp 참조 동일성, CommitAbility 반환값, bValid, Notify 도달 여부 등 단계별 검증
- 원인 2개 확정 후 수정 반영 (빌드는 사용자 수행)

## 확정한 설계

- Weapon GA는 EntityContext 캐시를 통해 로컬 침라 기능을 요청 — Ability마다 Context 재해석 불필요
- 발사체는 스폰 회전이 아닌 ShotDirection 벡터로 발사 (0벡터 시 전방 폐백)
- 공격 조건 판정은 STC가 담당 — GA 낶의 Can 계열 함수는 GA 자신의 ActivationOwnedTags에 의해 항상 false가 되므로 사용 금지
- 자동 재장전은 StateTree 흐름 안에서 처리: STT가 요청 설정 → STC가 요청 소비해 전이
- 충전식 구현은 버퍼에 Released 추가 없이 `IsInputHeld` 해제 감지로 가능 (확정, 미구현)
