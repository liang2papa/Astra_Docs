# 2026-08-16 일일 개발 리포트

## 오늘의 목표

- 권총 재장전 기능을 Upper StateTree, GAS, WeaponComponent 흐름에 맞춰 구현
- 재장전 애니메이션과 실제 탄약 충전 시점을 Anim Notify로 연결
- 카메라 Pitch 제한과 권총 조준 상태의 왼손 고정 결과 확인
- 구현 중 발생한 C++ 컴파일 오류와 무기 런타임 모델 참조 구조 정리

## 완료한 작업

### 1. 카메라 및 조준 상태 확인

- PlayerCameraManager를 통한 카메라 Pitch 최소·최대 제한을 적용함.
- 비무장 상태와 권총 상태에서 카메라 Pitch 제한이 정상적으로 적용되는 것을 확인함.
- 카메라 입력값과 Aim Pitch 전달이 정상적으로 동작하는 것을 확인함.

### 2. 권총 왼손 IK 구성

- 권총에 `LeftHandGrip` 소켓을 사용하도록 구성함.
- Anim Blueprint에서 무기 소켓 Transform을 캐릭터의 손 본 공간으로 변환하도록 연결함.
- Control Rig 이후에 FABRIK을 배치하여 왼손이 권총 손잡이를 따라가도록 구성함.
- 무기를 꺼냈을 때 왼손이 붙고, 무기를 넣었을 때 IK가 해제되는 것을 확인함.
- 현재 손이 소켓에서 약간 떨어져 보이고 상하 조준 시 팔이 조금 비틀리는 현상이 있으나, 기능 진행을 우선하여 세부 보정은 보류함.

### 3. 재장전 Blueprint 흐름 구성

- 기존 `IA_Astra_Reload` 입력을 재장전 요청 흐름에 연결함.
- `GA_WeaponReload` Gameplay Ability를 구성함.
- `STC_CanReload`에서 재장전 진입 가능 조건을 검사하도록 구성함.
- `STT_Reload`에서 재장전 Ability를 활성화하고 결과를 StateTree에 반환하도록 구성함.
- `ST_UpperState`에 Reload 상태와 관련 트랜지션을 연결함.
- 권총 재장전 몽타주를 연결하고 `Weapon_ReloadCommit` Anim Notify를 추가함.

### 4. 재장전 C++ 로직 구현

- `UWeaponComponent`가 재장전 몽타주 재생, Notify 수신, 탄약 반영, 완료 및 취소를 관리하도록 구현함.
- `CanReload`, `ExecuteReload`, `CancelReload`와 재장전 상태 조회 기능을 추가함.
- `FOnWeaponReloadFinished` 델리게이트를 통해 재장전 종료 결과를 외부에 전달하도록 구성함.
- 탄약은 몽타주 시작 시점이 아니라 `Weapon_ReloadCommit` Notify가 실행되는 시점에만 충전하도록 확정함.
- Notify 이전에 취소되면 탄약이 충전되지 않고, Notify 이후에 취소되면 이미 반영된 탄약은 유지되도록 구성함.
- 무기 해제, 수동 수납, 강제 수납 시 진행 중인 재장전을 취소하도록 연결함.
- 재장전 중에는 자동 수납 타이머가 작동하지 않도록 처리함.
- `UWeaponModel::CanReload()`가 탄약 사용 여부, 현재 탄약, 탄창 최대치를 기준으로 판단하도록 수정함.
- `Event.State.Upper.ReloadEntered` Gameplay Tag를 추가하고, EntityStateMediator가 재장전 진입 시 Sprint를 취소하도록 연결함.
- `State.Combat.Reloading` 태그는 GA 활성화 중 이미 적용되는 태그이므로 `CanReload()`의 금지 조건으로 중복 검사하지 않도록 정리함.

### 5. 런타임 모델 참조 정리

- 새 `CurrentWeaponModel` 변수를 추가하지 않고 기존 `EquippedWeaponModel`을 재사용하도록 정리함.
- 정적 설정은 `WeaponDataAsset`, 장착된 무기의 동적 탄약 상태는 `EquippedWeaponModel`, 실행과 애니메이션 제어는 `WeaponComponent`가 담당하도록 역할을 유지함.

### 6. 컴파일 오류 수정

- 지역 변수 `OwnerCharacter`가 클래스 멤버 `OwnerCharacter`를 가리던 C4458 오류를 수정함.
- Anim Notify 처리 코드의 잘못된 식별자 `BranchingPointNotifyPayload`를 실제 매개변수인 `BranchingPointPayload`로 수정함.
- 수정 후 Development Editor 빌드가 완료되는 것을 확인함.

## 확정한 설계

- StateTree는 입력에 따른 상태 선택과 사전 조건 검사를 담당함.
- GAS Ability는 재장전 행동의 활성화와 종료 수명주기를 담당함.
- WeaponComponent는 재장전 실행, 몽타주, Notify, 탄약 반영, 취소를 담당함.
- WeaponModel은 장착된 개별 무기의 현재 탄약을 포함한 동적 상태를 소유함.
- WeaponDataAsset은 최대 탄약, 재장전 몽타주 등 무기별 정적 데이터를 소유함.
- 재장전 탄약 반영은 반드시 `Weapon_ReloadCommit` Notify에서 수행하며 몽타주 종료 시 자동 보정하지 않음.
- Fire, Aim, Reload 진입은 Sprint를 취소하며, 행동 종료 후 Sprint를 자동 복구하지 않음.
