# 2026-08-26 일일 개발 리포트

> 집계 시간: 2026-08-26 09:00 ~ 2026-08-27 09:00

## 오늘의 목표

- Player Blueprint에 있던 조준·Draw 런타임 계산을 책임 컴포넌트로 이관
- 이동·공중 상태를 포함한 무기 명중률 기준 확정
- PlayerHUD C++ 기반과 체력·스테미너·무기 정보 UI 구현

## 완료한 작업

### 1. 무기 회전 모드 점검

- 무기 활성화 시 캐릭터가 카메라 Yaw를 따라가는 주체가 `ApplyWeaponRotationMode()`임을 확인함.
- `Use Controller Desired Rotation`은 항상 비활성화되어 있고, 무기 활성 상태에서는 `Use Controller Rotation Yaw`가 사용됨을 정리함.
- Fire Montage를 다른 각도에서 관찰할 때 PIE 인스턴스의 회전 설정을 임시 변경하는 절차를 정리함.

### 2. Blueprint 런타임 함수 책임 분리

- `UpdateWeaponVisualAimCorrection`, `UpdateWeaponAimSolution`, `ResetWeaponVisualAimCorrection`을 WeaponComponent 책임으로 이관하는 방향을 확정함.
- 디버그 전용 `CheckMuzzleDirection`은 BP_PlayerCharacter에 유지함.
- Draw 정렬 함수는 Weapon 상태와 이동 방향 판정이 섞여 있어 그대로 LocomotionComponent로 옮기지 않도록 함.
- LocomotionComponent에는 `IsFacingControlRotation(YawTolerance)` 같은 순수 방향 판정만 두도록 함.
- PlayerCharacter는 WeaponComponent의 정렬 대기 상태와 LocomotionComponent의 판정 결과를 중재해 Draw 완료를 통지하도록 함.
- 기존 Blueprint 함수는 C++ 경로 검증 전까지 비교·복구 기준으로 보존하도록 함.

### 3. 무기별 조준 설정 데이터화

- `VisualAimCorrectionInterpSpeed`, `MaxVisualAimCorrectionPitch/Yaw`, `WeaponDrawAlignmentToleranceYaw`를 WeaponDataAsset로 이동하도록 함.
- 기본값을 보간 속도 10, 최대 Pitch/Yaw 30도, Draw 정렬 허용 오차 5도로 정함.
- Aim Trace Channel과 Debug Color를 `UpdateWeaponAimSolution` 입력으로 전달하도록 설계함.
- 기본 Trace Channel은 조준·시야 판정에 적합한 Visibility로 유지함.
- Debug Color Alpha가 0이면 디버그 그리기 함수 자체를 호출하지 않도록 함.
- 발사 중에도 Aim Solution은 갱신하되 Visual Aim Correction의 Update·Reset만 중지하여 Fire Montage가 보정에 의해 상쇄되지 않도록 함.

### 4. 명중률 기준 확정

- 다수의 적을 상대하는 전투 특성을 고려해 공중 조준 사격을 과도하게 제한하지 않기로 함.
- 정지 조준 100, 정지 미조준 80, 이동 조준 80, 점프 조준 80, 이동·점프 미조준 0을 초기 기준으로 확정함.
- `AirborneHipFireAccuracyPenalty = 80`, `AirborneAimingAccuracyPenalty = 20` 기준을 정함.
- 공중 상태와 지상 이동 페널티를 중복 적용하지 않고 `Airborne → Ground Moving → Ground Stationary` 우선순위를 사용하도록 함.
- 명중률 0은 강제 빗나감이 아니라 최대 Spread Angle 전체를 사용하는 의미로 정리함.

### 5. 발사 방식 구현 범위 점검

- 현재 일반 총기 발사는 SingleShot만 완성되어 있음을 확인함.
- RapidFire, ThreeShot, ChargedShot은 데이터 또는 Enum만 있고 반복·입력 수명주기 처리가 아직 없음.
- Continuous는 일반 연사가 아니라 Beam 계열 지속 공격 처리로 구분함.
- 후속 무기 작업으로 RapidFire와 Rifle·Melee·Unarmed별 Anim Layer 구성을 남김.

### 6. PlayerHUD C++ 구조 설계 및 적용

- HUD 데이터 출처를 체력 `EntityHealthComponent`, 스테미너·SP `PlayerStatusModel`, 탄약 `WeaponComponent`, 무기 정보 `WeaponDataAsset`으로 정함.
- 장기적으로 데이터 소유자가 바뀌더라도 Widget이 모델을 직접 참조하지 않도록 이벤트 중재 구조를 사용함.
- 실행 흐름을 `게임플레이 컴포넌트 → PlayerCharacter → PlayerController → PlayerHUDComponent → PlayerHUDWidget`으로 구성함.
- `UPlayerHUDWidget`을 실제 View, `UPlayerHUDComponent`를 Widget 수명과 데이터 전달 창구, `AAstraPlayerController`를 Pawn 교체 중재자로 구분함.
- UserWidget/UMG를 게임 HUD에 사용하고 저수준 C++ UI인 Slate는 사용하지 않도록 함.
- HUD C++ 기반 코드 적용과 빌드는 사용자 측에서 완료함.

### 7. 체력 HUD 구현

- `WBP_PlayerHUD`를 생성하고 C++ `UPlayerHUDWidget` 기반 이벤트를 구현함.
- 체력 현재값/최대값, 0~1 Clamp 및 Progress Bar 갱신을 연결함.
- Canvas Panel, Overlay, Progress Bar와 체력 텍스트의 계층과 임시 위치를 구성함.
- Rich Text Block의 유효하지 않은 폰트로 Last Resort Glyph가 표시되던 문제를 수정함.
- PIE에서 체력 게이지와 현재/최대 체력 표시가 정상 동작하는 것을 확인함.

### 8. 스테미너·탈진 HUD 구현

- 체력 영역을 복제해 스테미너 Progress Bar와 값 표시를 추가함.
- HUD 초기 동기화가 StatusModel 초기화보다 먼저 실행되어 0/0으로 보이던 순서 문제를 확인함.
- 초기화 완료 후 현재 스테미너 상태를 다시 발행·동기화하도록 정리함.
- 스테미너 소모와 회복, 탈진 상태 표시까지 연결함.

### 9. 무기 아이콘·탄약 HUD 구현

- Soul Energy는 보류하고 무기 정보 영역을 우선 구현함.
- WeaponDataAsset의 HUD Icon을 Widget Image에 연결함.
- 현재 탄약/최대 탄약 이벤트를 Text에 연결하고 발사 시 갱신하도록 함.
- 루트 Canvas 아래에 무기 정보용 Canvas Panel을 두어 아이콘과 탄약 텍스트를 자유 배치함.
- Stretch Anchor 때문에 작은 화면에서 아이콘이 과도하게 축소되던 문제를 단일 점 Anchor와 고정 크기로 수정함.
- 초기 HUD 동기화와 무기 장착 이벤트의 호출 순서를 분석하고 최종 무기 보유 상태가 정상 전달됨을 확인함.
- 무기 아이콘과 탄약 표시, 발사 시 감소 반영을 완료함.

### 10. 문서 현행화

- 무기 조준·반동·명중률 문서에 현재 반동·명중률 데이터, 계산 흐름 및 미구현 실제 탄도 범위를 반영함.
- Player Blueprint 정렬 검사와 AimOffset 왼손 이탈을 완료 상태로 변경함.
- FABRIK 중복 적용이 왼팔 분리 원인이었음을 기록함.
- 명중률에서 Spread Angle과 원뿔 방향 샘플링, HUD 확산 반경 공유 구조를 문서화함.
- 문서명을 `무기 조준·반동·명중률`로 변경하고 관련 링크를 갱신함.

## 확정한 설계

- 조준·총열 보정은 WeaponComponent, 방향 판정은 LocomotionComponent, 컴포넌트 중재는 PlayerCharacter가 담당함.
- 무기별 시각 보정과 Draw 허용 오차는 WeaponDataAsset에서 편집함.
- 발사 중 Aim Solution은 유지하되 Visual Correction 값은 고정함.
- 공중 조준 사격 기준 명중률은 80, 공중 미조준은 0으로 설정함.
- HUD는 PlayerController가 소유하고 PlayerCharacter 이벤트를 통해 현재 Pawn 데이터를 전달받음.
- Widget은 표현만 담당하며 게임플레이 모델을 직접 조회하지 않음.
