# 2026-09-17 일일 개발 리포트

## 오늘의 목표

- EntityContext 참조 경계 확장
- 스프린트 초당 스태미너 소모 경계 정리
- 매달림 상태 표현 이벤트 추가
- ABP 초기화 구조 정리 (스레드 세이프 경고 해결)

## 완료한 작업

### 1. EntityContext 확장

- PlayerCameraManager 참조를 EntityContext가 보관하도록 추가
- `SetPlayerCameraManager` 추가 — 로컬 PlayerController가 관리하는 참조를 Context에 주입
- Context는 참조만 보관하고 판단·전이 로직은 포함하지 않는 원칙 유지

### 2. 스태미너 부분 소모 경계 추가

- `TrySpendStamina`에 `bAllowPartialSpend` 파라미터 추가
- 기본값 false — 전액 지불 가능할 때만 소모 (점프·회피 등 일회성 비용)
- true — 부족하면 남은 만큼만 소모해 정확히 0에 도달 (스프린트 등 초당 소모)

### 3. 매달림 상태 변경 이벤트

- EntityLocomotionComponent에 `OnLedgeGrabStateChanged` 이벤트 추가
- LedgeGrabbed 상태 변화 시 발행

### 4. 조준 솔루션 캐시 정리

- AimHandler의 Aim 해결 값(ShotDirection 포함)을 캐시해 재사용하도록 정리

### 5. AAstraPlayerController 소스 반영

- Entity 명령 전달과 침라 참조 갱신 경로 소스 반영

### 6. ABP 초기화 구조 정리

- `InitABPClass` 함수 신설 — 플레이어 BeginPlay에서 ABP를 캐스팅 후 컴포넌트 일괄 주입, `bIsInitialized`로 완료 표시
- ABP의 `UpdateAnimation` 에러(캐싱 타이밍) 해결
- 스레드 안전 경고(`Get LocomotionComp`) 해결 — 멀티스레드 애니메이션 업데이트는 유지 (NPC 다수 생성 게임이므로)

### 7. PlayerContext 생성 타이밍 정리

- "PlayerContext was missing and has been recreated" 재생성 경고 해결
- 컨텍스트는 생성자가 아닌 **BeginPlay에서 생성+초기화**로 결정

### 8. 리로드 완료 처리 수정 (BP)

- 리로드 GA가 활성화돼도 즉시 캔슬되던 문제 해결
- 원인: STT_WeaponReload Tick의 `FinishTask`를 Branch 없이 태그 결과에 직접 연결한 wiring 오류
- 교훈: Tick에서 FinishTask는 반드시 "완료 조건일 때만" Branch로 호출

### 9. 크로스헤어 표시 수정 (BP)

- 조준 STT 진입 시 CarryState가 Ready가 아니면 `EnterReadyCarryState()` 호출
- `ExecuteDrawWeapon`은 몽타주 기반 Draw 절차라 몽타주 없는 흐름에서 손 부착이 안 되어 크로스헤어가 비활성이던 문제 해결

### 10. 조준 FOV 기반 마련

- `AstraWeaponGameplayAbilityBase`에 `GetEntityContext`, `GetWeaponComponent` 추가 — 캐시 null 시 Avatar의 EntityContext lazy 재해석
- `StartAimCameraFOV`, `StopAimCameraFOV`가 이 getter를 사용하도록 교체 → 에임 FOV 정상 작동 확인

## 확정한 설계

- 스프린트 초당 소모는 STT가 프레임당 `TrySpendStamina(비용 × DeltaTime, 부분 소모 허용)` 형태로 호출
- 일회성 비용(점프·회피)과 초당 소모(스프린트)를 하나의 함수 경계로 처리하되 부분 소모 여부로 구분
- 컨텍스트/컴포넌트 초기화는 생성자(생성)와 BeginPlay(초기화)로 분리
- STC는 조건 판정, STT/GA는 수행 — 조건 검사의 이중 배치 주의 (GA의 ActivationOwnedTags는 ActivateAbility 시작 전에 이미 부착됨)
