# 2026-09-08 일일 개발 리포트

> 집계 시간: 2026-09-08 09:00 ~ 2026-09-09 09:00

## 오늘의 목표

- Inventory Tooltip의 C++ ViewData와 Blueprint 표시 흐름 정리
- Item 종류 전환 시 Tooltip에 이전 데이터가 남는 문제 방지
- CSV·Manifest 기반 Item DataAsset 생성 구조의 확장 방향 검토
- 테스트용 Item·Weapon·Ammunition DataAsset 및 Player 에셋 갱신

## 완료한 작업

### 1. Tooltip ViewData 계약 단순화

- `FItemTooltipViewData`를 UI 표시용 값 스냅샷으로 유지하고, Blueprint가 원본 ItemInstance와 DataAsset을 직접 해석하지 않도록 역할을 정리함.
- 공통 정보로 Item 이름, 분류, 희귀도, 아이콘, 수량, 최대 Stack, 단위·총무게를 전달하도록 구성함.
- Equipment와 Weapon 표시 정보로 장비 종류, 현재·최대 내구도, 무기 종류와 기본 피해량을 전달하도록 구성함.
- `bBroken`은 별도 상태로 보관하지 않고 현재 내구도가 0인지 여부로 판단하도록 정리함.
- 종류별 표시 여부 Boolean을 중복 보관하지 않고 ItemCategory·EquipmentType과 실제 값으로 표시 대상을 결정하도록 정리함.

### 2. InventoryMenu의 Tooltip 데이터 생성 흐름 정리

- InventoryMenuComponent가 선택한 ItemInstance를 기준으로 `FItemTooltipViewData`를 조합하는 구조를 유지함.
- InventoryMenuWidget의 Tooltip Event가 원본 ItemInstance 대신 완성된 ViewData를 받도록 연결함.
- Item·Equipment·Weapon·Ammunition별 DataAsset 해석은 C++ 중계 계층에서 처리하고 Widget은 표시 책임에 집중하도록 함.

### 3. Tooltip Blueprint 표시 순서 갱신

- `WBP_InventoryMenu`에서 Tooltip 표시 요청 시 기존 데이터를 먼저 초기화한 뒤 공통 데이터를 적용하도록 실행 순서를 정리함.
- 공통 데이터 표시 후 ItemCategory를 분기하고, Equipment인 경우 EquipmentType을 다시 분기하여 Weapon 데이터를 표시하도록 구성함.
- Item 종류가 바뀔 때 이전 Weapon 정보가 남지 않도록 세부 정보 Panel을 먼저 `Collapsed` 상태로 초기화하도록 함.
- `WBP_ItemTooltip`과 `WBP_InventoryMenu` 에셋에 신규 ViewData 표시 흐름을 반영함.

### 4. 수치 표시 정밀도 유지

- 내구도와 피해량은 UI 전달 과정에서 `float` 값을 유지하도록 함.
- 정수 형태의 표기가 필요한 경우 원본 값을 절삭해 저장하지 않고 최종 `ToText` 단계에서 표시 형식만 조정하도록 정리함.

### 5. Item·Weapon 테스트 에셋 갱신

- Player DataAsset과 PlayerCharacter Blueprint의 Item·Inventory 연동 설정을 갱신함.
- ItemActor, 9mm Ammunition, Base Pistol 및 Base AR DataAsset을 현재 Item 데이터 구조에 맞춰 갱신함.
- QuestItem·Miscellaneous·Ingredient 폴더의 안내용 DataAsset을 정리함.
- Item과 Inventory 동작 확인에 사용하는 테스트 Level 에셋을 정리함.

## 설계 검토

### CSV·Manifest 확장 구조

- `ItemAssetManifest.csv`의 열은 `ItemID`, `DefinitionType`, `AssetFolder`, `AssetName`으로 고정하고 Item 추가 시 행을 늘리는 현재 구조를 확인함.
- 장기적으로 Manifest에는 `ItemID`와 `DefinitionType`만 두고 폴더와 Asset 이름은 명명 규칙으로 생성하는 단순화 방향을 검토함.
- 신규 Weapon 세부 CSV가 추가될 때마다 Importer 코드에 Table 선언·Load·배열 등록을 반복해야 하는 확장성 문제를 확인함.
- CSV Source 메타데이터를 이용해 세부 Table을 자동 탐색하고 적용하는 구조를 후속 개선 방향으로 정리함.

## 확정한 설계

- Tooltip Widget은 C++에서 조합된 `FItemTooltipViewData`만 표시함.
- Item 종류별 표시 상태는 중복 Boolean이 아니라 Category·Type과 실제 데이터로 결정함.
- 파손 여부는 현재 내구도 0으로 판단하며 별도 `bBroken` 필드를 두지 않음.
- 수치 데이터는 원본 정밀도를 유지하고 최종 표시 단계에서만 서식을 적용함.
- Tooltip 갱신 시 모든 세부 Panel을 초기화한 뒤 현재 Item 종류에 필요한 영역만 표시함.

## 테스트·검토 결과

- `WBP_InventoryMenu`와 `WBP_ItemTooltip`에 ViewData 기반 표시 흐름을 반영함.
- Weapon에서 다른 Item 종류로 선택을 바꿀 때 이전 세부 정보가 남지 않도록 초기화 순서를 구성함.
- Player, ItemActor, Ammunition 및 Weapon DataAsset과 테스트 Level 에셋을 갱신함.
- CSV·Manifest와 Weapon 세부 Table Importer의 현재 확장 지점을 정적 검토함.
- Item 종류별 Tooltip 표시 결과와 변경 에셋의 전체 PIE 회귀 검증은 추가로 필요함.
