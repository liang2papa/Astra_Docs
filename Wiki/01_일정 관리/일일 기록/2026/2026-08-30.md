# 2026-08-30 일일 개발 리포트

> 집계 시간: 2026-08-30 09:00 ~ 2026-08-31 09:00

## 오늘의 목표

- Inventory·Gear 메뉴의 C++ 기반 구축
- 인벤토리 아이템 분할·장착·해제·드롭 흐름 연결
- WorldItem 생성과 재사용 구조 구현
- 탄약 획득·재장전 테스트 데이터 및 조건 정리

## 완료한 작업

### 1. Inventory Menu C++ 기반 구현

- `UInventoryMenuComponent`와 `UInventoryMenuWidget`을 추가함.
- PlayerController가 InventoryMenuComponent를 소유하고 Enhanced Input으로 메뉴를 토글하도록 연결함.
- 메뉴 열기·닫기 시 Widget 생성, Viewport 표시, Mouse Cursor 및 GameAndUI/GameOnly 입력 모드를 전환하도록 함.
- Inventory·Gear 데이터 소스를 연결하고 슬롯·Capacity·장비 변경 이벤트를 구독하도록 함.
- 메뉴가 열릴 때 전체 슬롯을 동기화하고 변경된 슬롯만 갱신하는 이벤트 기반 구조를 구성함.

### 2. Inventory UI 행동 API 구현

- Inventory Item과 Gear Item 선택 및 Tooltip 표시 요청을 추가함.
- Inventory·Gear Context Menu를 열고 현재 Item 상태에 따라 장착·해제·분할·드롭 가능 여부를 전달하도록 함.
- 호환 가능한 Equipment Slot 선택, Stack 분할 수량 입력 및 실패 메시지 전달 API를 구성함.
- Widget은 표현만 담당하고 실제 Item 이동은 InventoryMenuComponent가 ItemTransferComponent에 요청하도록 책임을 구분함.

### 3. Stack 분할과 Item 드롭 흐름 구현

- InventoryComponent에 Stack 분할을 지원하는 기능을 보완함.
- ItemTransferComponent에 Inventory Item 및 장착 Item의 드롭 가능 여부와 실제 드롭 요청을 추가함.
- 드롭 전에 원본 Item 이동 가능 여부와 WorldItem 생성 가능 여부를 검사하도록 함.
- Inventory 또는 Gear에서 제거한 ItemInstance를 WorldItem으로 옮기는 흐름을 구성함.
- 실패 시 원본 Item 상태를 보존할 수 있도록 준비·활성화 단계를 분리함.

### 4. WorldItem Factory와 Pool 기반 구현

- `UWorldItemFactorySubsystem`과 `UWorldItemFactorySettings`를 추가함.
- WorldItem Actor Class 및 Spawn 설정을 프로젝트 설정에서 지정할 수 있도록 함.
- 드롭 시 WorldItem을 바로 파괴·재생성하지 않고 Factory Pool에서 획득해 재사용할 수 있도록 구성함.
- WorldItem의 Prepare, Activate, Cancel 및 비활성화 흐름을 분리함.
- WorldItem이 보유 Item을 모두 잃으면 Pool로 반환되고 다음 드롭에서 다시 초기화되도록 함.

### 5. WorldItem 표시·획득 구조 보완

- WorldItem의 Display Mesh 갱신과 Soft Reference 비동기 로딩 흐름을 Pool 재사용 구조에 맞게 보완함.
- 재사용 전 이전 Item, Mesh Load Handle, Collision 및 활성 상태가 남지 않도록 정리함.
- ItemInstanceFactorySubsystem과 WorldItemFactorySubsystem의 생성 책임을 구분함.
- 전자는 ItemInstance와 Runtime ID를 생성하고 후자는 이를 담는 월드 Actor를 생성·재사용하도록 함.

### 6. 탄약·Reload 테스트 에셋 정리

- 탄약 획득 테스트용 Blueprint와 9mm 탄약 DataAsset을 구성함.
- `STC_CanReload`를 현재 Inventory 탄약·WeaponInstance 구조에 맞게 조정함.
- 탄약이 탄창 Reservation으로 모두 사용 중이면 추가 사용 가능 수량이 0이라는 기준을 테스트 흐름에 반영함.

## 확정한 설계

- Inventory 메뉴 실행과 입력 관리는 PlayerController 소유 InventoryMenuComponent가 담당함.
- Widget Blueprint는 표시와 사용자 선택 전달만 담당함.
- Item 이동·장착·해제·분할·드롭은 ItemTransferComponent를 통해 실행함.
- WorldItemFactorySubsystem이 WorldItem Actor의 생성과 Pool 재사용을 담당함.
- ItemInstanceFactorySubsystem은 런타임 ItemInstance 생성만 담당함.

## 테스트·검토 결과

- Inventory Menu의 입력·데이터 바인딩·행동 요청 C++ 흐름을 정적 검토함.
- WorldItem 준비·활성화·취소·Pool 반환 흐름을 확인함.
- 탄약 테스트 DataAsset과 Reload Condition 에셋을 구성함.
- UMG·Slate 의존성을 Build 설정에 반영함.
- 전체 Widget Blueprint 조립과 기능별 PIE 검증은 아직 남아 있음.
