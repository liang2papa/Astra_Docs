# 2026-08-25 일일 개발 리포트

> 집계 시간: 2026-08-25 09:00 ~ 2026-08-26 09:00

## 오늘의 목표

- Control Rig와 FABRIK 없이 총열이 AimTarget을 향하도록 상체 시각 보정 구현
- Fire Montage와 조준 Pose의 충돌 원인 분석
- 무기별 반동·명중률·내구도 데이터 및 실행 기반 구현
- Draw 방향 정렬 이후 발생한 Fire 회귀 문제 해결

## 완료한 작업

### 1. 총열 시각 보정 방식 재정의

- 현재 AnimGraph에서 Control Rig와 FABRIK을 사용하지 않는 상태를 확인함.
- 왼손은 IK가 아니라 `AimOffset_Pistol`의 Additive Pose와 원본 애니메이션 자세로 유지됨을 기준으로 설계를 수정함.
- 오른팔이나 무기만 회전시키지 않고 `spine_01`부터 상체 전체를 회전해 양손의 상대 위치를 유지하도록 함.
- AnimGraph의 `Transform (Modify) Bone`을 이용해 Yaw·Pitch 보정값을 적용하도록 구성함.
- 적용 순서를 `Aim Offset → Layered Blend Per Bone → Component Space 변환 → spine 보정 → Local Space 복귀 → Output Pose`로 정리함.

### 2. Muzzle 방향 차이 계산

- 현재 총열 방향을 Muzzle Transform의 Forward Vector로 계산함.
- 목표 총열 방향을 `Normalize(AimTargetLocation - MuzzleLocation)`으로 계산함.
- `Normalized Delta Rotator`의 A에는 DesiredMuzzleRot, B에는 CurrentMuzzleRot을 연결하도록 함.
- 목표 방향과 카메라 방향을 비교하던 잘못된 연결을 제거함.
- Current Muzzle과 Desired Muzzle Debug Arrow가 모두 Muzzle Location에서 시작하도록 정리함.
- BP_PlayerCharacter에 현재·목표 보정값과 최대 보정각, 보간 속도 변수를 구성함.

### 3. Tick 및 보간 함수 정리

- `UpdateWeaponVisualAimCorrection`에서 현재 총열, 목표 총열, Delta Yaw/Pitch, Clamp 및 `FInterp To`를 처리하도록 함.
- `ResetWeaponVisualAimCorrection`에서 현재 보간값을 0으로 복귀시키도록 함.
- Reset 함수의 `FInterp To.Current`에 목표값 0이 연결되어 즉시 초기화되던 오류를 수정함.
- Aim Solution 갱신 성공 시 보정 함수를, 실패·수납 시 Reset 함수를 호출하도록 실행 흐름을 구분함.
- Yaw 보간의 Target에 Pitch 목표값이 연결된 오류를 찾아 각각 올바른 목표 변수로 수정함.
- `MaxVisualAimCorrectionYaw/Pitch` 기본값이 0이라 모든 결과가 Clamp 0이 되던 문제를 확인하고 30도로 설정함.

### 4. AnimBP 연결 및 축 검증

- ABP에 `WeaponVisualAimCorrectionYaw/Pitch` 변수를 추가함.
- 매 프레임 Cast하지 않고 기존에 캐싱된 BP_PlayerCharacter 참조에서 보간 완료 값을 복사하도록 함.
- 목표값인 `TargetVisualAimCorrectionYaw` 대신 현재 보간값 `VisualAimCorrectionYaw`를 전달하도록 수정함.
- `spine_01`, Add to Existing, Component Space 설정으로 Transform Bone을 구성함.
- 고정 Yaw 20 테스트로 상체 회전이 실제 적용되는 것을 확인함.
- 스켈레톤의 Bone 축이 일반 Rotator 의미와 다름을 확인함.
- Pitch 값을 직접 적용하면 우측 비틀림이 발생하고 Roll 값이 전후 숙임을 만든다는 것을 테스트함.
- 논리 Pitch 보정값을 AnimGraph의 Roll 축으로 변환해 적용하도록 정리함.

### 5. Fire Montage와 조준 Pose 충돌 분석

- 일반 Fire Montage가 기존 조준 중인 어깨·척추 Pose를 자신의 원본 Pose로 덮어써 빠르게 회전하고 복귀하는 원인을 확인함.
- Fire 전용 Slot에서 양팔 Pose만 적용하는 방안과 조준 Pose 기준 Additive Fire 애니메이션 방안을 비교함.
- 오른팔만 분리하지 않고 양팔을 함께 적용해야 양손 관계가 유지됨을 정리함.
- Reload에 영향을 주지 않도록 Fire 전용 Slot을 별도로 사용하는 방향을 검토함.
- Lyra의 Fire 애니메이션이 Mesh Space Rotation Offset Additive로 구성되어 어깨 전환이 자연스러운 점을 확인함.
- Astra의 Fire 애니메이션도 기준 프레임 대비 Additive 형태로 제작하는 방향을 정리함.

### 6. 반동·명중률·내구도 기반 구현

- 반동 수치는 WeaponDataAsset이 소유하도록 함.
- Pitch/Yaw 반동 Min/Max, 최대 누적 반동 및 회복 시간을 추가함.
- 발사 입력이 일정 시간 없을 때 누적 반동이 감소하는 일반 TPS 방식으로 회복 조건을 정함.
- 반동 회복 중 플레이어가 카메라를 조작하면 자동 회복을 중단하도록 함.
- WeaponComponent가 반동을 누적하고 이벤트를 발행하며 PlayerCharacter가 PlayerCameraManager에 전달하도록 함.
- 실제 발사 방향 반동은 우선 적용하지 않고 카메라 반동만 구현 범위로 둠.
- WeaponModel에 현재 내구도와 내구도 변경 이벤트를 추가함.
- WeaponDataAsset에 최대 내구도, 기본·조준·이동 명중률 보정값과 최대 탄 퍼짐 각도를 추가함.
- 명중률 데이터와 계산 함수는 구성하되 실제 ShotDirection에는 아직 연결하지 않음.

### 7. C++ 경고 및 애셋 연결 수정

- 외부에 노출되지 않는 `UPROPERTY(Transient)`에 Category만 지정해 발생한 UHT 경고를 수정함.
- PlayerCharacter와 WeaponComponent 내부 전용 런타임 변수에서 불필요한 Category를 제거함.
- Additive Fire Montage에 `Weapon_FireCommit` Notify가 없는 이전 경로가 DataAsset에 연결된 문제를 확인함.
- 올바른 Astra 경로의 Fire Montage와 Notify를 사용하도록 애셋 참조를 점검함.

### 8. Draw 정렬 회귀 진단 및 수정

- Fire 입력은 `RequestWeaponFire → RequestWeaponDraw(Fire) → Drawing`까지 정상 진입함을 로그로 확인함.
- Draw Montage 제거 후 추가한 `bWaitingForDrawAlignment`가 완료되지 않아 Drawing 상태에서 멈추는 회귀를 확인함.
- PIE 시작 후 첫 입력 전 이동이 안 되던 현상은 Game Gets Mouse Control 설정에 따른 뷰포트 포커스 문제로 무기 회귀와 분리함.
- `WeaponDrawAlignmentToleranceYaw = 5`, 실제 Abs Delta Yaw = 0인데 완료 Notify가 호출되지 않는 점을 추적함.
- Blueprint의 `<=` 입력이 `Tolerance <= Delta`로 반대로 연결되어 있던 원인을 확인함.
- 비교식을 `Abs Delta Yaw <= WeaponDrawAlignmentToleranceYaw`로 수정하여 정렬 완료 경로를 복구함.
- 디버그 결과 조회도 Fire 결과가 아니라 Draw 결과를 확인하도록 정리함.

### 9. Fire 중 시각 보정 정책

- `Transform (Modify) Bone`이 Fire Montage 뒤에서 실행되고, 매 Tick 총열을 AimTarget에 다시 맞춰 Montage 반동을 상쇄하는 문제를 확인함.
- 발사 중에도 Aim Solution과 Debug 방향 계산은 유지하도록 함.
- `Is Fire In Progress` 동안 Visual Aim Correction 값을 새로 갱신하거나 0으로 Reset하지 않고 발사 직전 값을 고정하는 진단 방안을 정리함.
- Fire Montage와 Additive 반동이 정상 보이는지 확인한 뒤 최종 적용 순서를 결정하기로 함.

### 10. 설계 문서 현행화

- `무기 조준·반동·명중률.md`에 총열 시각 보정 결과, 반동 누적·적용·회복, 명중률·내구도 구조를 반영함.
- 무기 시스템 문서에 WeaponDataAsset, WeaponModel, WeaponComponent 책임 확장을 반영함.
- 애니메이션과 조준 문서에 Pitch/Yaw 검증과 Fire Montage 시각 변화 내용을 추가함.
- 개발 규칙에 헤더 주석과 Blueprint 카테고리 정리 기준을 추가함.
- 남은 이슈에서 완료된 총열 보정을 해결 항목으로 이동하고 반동 PIE, 실제 탄도 및 HUD 연결을 후속 작업으로 갱신함.

## 확정한 설계

- 총열 시각 보정은 Control Rig·FABRIK 없이 spine 계열 Transform Bone으로 처리함.
- BP_PlayerCharacter는 Muzzle과 AimTarget 차이를 계산하고 ABP는 보간 완료 값을 Pose에 표현함.
- 스켈레톤 축에 맞춰 논리 Pitch는 spine Roll 축으로 변환함.
- Fire 애니메이션은 조준 Pose 기준 Additive 방식이 우선 대안임.
- 반동 데이터는 WeaponDataAsset, 누적 상태는 WeaponComponent, 카메라 적용은 PlayerCameraManager가 담당함.
- 내구도는 WeaponModel의 런타임 상태로 관리함.
- Draw 상태는 방향 정렬 완료 Notify 이후에만 Ready와 Pending Action으로 진행함.
- 코드 수정 전에는 변경 대상 함수·클래스의 전문을 먼저 제시하고 확인받음.
