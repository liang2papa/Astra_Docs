# 2026-08-18 일일 개발 리포트

## 오늘의 목표

- 팀원이 프로젝트를 받은 뒤 발생한 레벨·솔루션·빌드 문제 원인 정리
- Aim 변경 이후 발생한 StateTree `None 접근` 오류의 실제 원인 확인
- Hanging 진입 시 무기 처리 정책 결정

## 완료한 작업

### 1. 협업 프로젝트 동기화 및 레벨 문제 분석

- 상대방에게 레벨이 보이지 않던 주요 원인으로 `.ignore`의 `/Content` 규칙을 확인함.
- 레벨 `.umap`, 관련 `.uasset`, World Partition의 `__ExternalActors__`, `__ExternalObjects__`를 함께 체크인해야 함을 정리함.
- 이전 브랜치의 레벨은 Content Browser 필터 초기화, Asset Registry 캐시 재생성, 필요 시 원본 브랜치에서 Migrate하는 절차로 복구하도록 안내함.
- 브랜치 전환 후 남은 `Binaries`, `Intermediate`, `.vs`, `DerivedDataCache`가 이전 소스와 충돌할 수 있음을 확인하고 프로젝트 파일 재생성 절차를 정리함.

### 2. `.slnx` 및 팀원 빌드 환경 점검

- 최신 Visual Studio 2022에서는 `.sln` 없이 `.slnx`만으로도 `Development Editor / Win64` 빌드가 가능함을 확인함.
- C++ 클래스 생성에는 Game Development with C++, MSVC v143, Windows SDK, Visual Studio Tools for Unreal Engine 구성이 필요함을 정리함.
- `BlueprintGraphClasses.h` 누락 오류는 `.slnx` 형식 문제가 아니라 생성 헤더·캐시 또는 프로젝트에 포함된 `VisualStudioTools 2.8` 플러그인과 UE 5.8 환경의 호환 문제로 분류함.

### 3. StateTree `None 접근` 오류 분석 및 해결

- 로그가 C++ 빌드 오류가 아니라 PIE 중 Blueprint StateTree 런타임 오류임을 구분함.
- 초기에는 `PlayerContext` 생성 상태를 점검하고, Blueprint에서 포인터가 덮어써지지 않도록 노출 속성과 타입을 보강함.
- `PostInitializeComponents()`에서 Context가 없을 경우 StateTree 시작 전에 복구하는 방어 경로를 추가함.
- 이후에도 `STT_PlayerIdle`, `STT_PlayerWalk`에서 Actor와 Context가 None인 오류가 지속되어 StateTree Task 자산을 재분석함.
- 부모 STT의 실제 프로퍼티가 `APlayerCharacter_New`, `PlayerContext_New`인 반면 StateTree 바인딩 대상은 기존 이름인 `APlayerCharacter`, `PlayerContext`로 남아 있음을 확인함.
- STT 부모 변수와 StateTree Task 바인딩을 다시 연결하여 `None 접근` 오류를 해결함.

### 4. Hanging과 무기 상태 정책 정리

- 처음에는 무기가 손에 있으면 `STC_CanHanging`에서 진입을 차단하는 방안을 검토함.
- 최종적으로 Hanging 진입은 허용하되 Traversal 진입 이벤트를 통해 현재 무기 행동을 취소하고 강제 수납하도록 방향을 변경함.
- 기존 `Event.State.Locomotion.TraversalEntered` → `Event.Command.Upper.CancelAction` 및 `Event.Command.Upper.ForceHolster` 흐름을 재사용하기로 함.
- Holster Montage 중 손이 벽에서 떨어지는 문제가 보이면 Hanging 전용 수납 모션 또는 즉시 수납 방식으로 후속 보정하기로 함.

## 확정한 설계

- `.slnx`는 지원되는 Visual Studio 환경에서 Unreal 솔루션 빌드에 사용 가능함.
- 협업 레벨은 단일 `.umap`만이 아니라 의존 에셋과 World Partition 외부 데이터를 함께 버전 관리함.
- StateTree 바인딩 오류는 화면상 연결 여부뿐 아니라 Blueprint 내부 실제 프로퍼티 이름과 저장된 바인딩 대상의 일치 여부까지 확인함.
- Hanging은 무기 소지 때문에 차단하지 않고 Traversal 진입 시 Mediator/EventBus를 통해 행동 취소와 강제 수납을 요청함.

## 테스트 결과

- `PlayerContext` 유효성 확인 후에도 지속되던 오류를 STT 바인딩 수정으로 해결함.
- `STC` 정상, `STT_PlayerIdle/Walk` 정상, PIE의 연쇄 `None 접근` 오류 해소를 확인함.
- 프로젝트 재생성 후 `.slnx`로 솔루션을 열 수 있음을 확인함.

## 잔여 이슈

- 팀원 환경의 `BlueprintGraphClasses.h` 오류가 캐시 정리 또는 `VisualStudioTools` 비활성화로 해결되는지 확인.
- `.ignore` 수정 후 레벨 및 World Partition 데이터가 실제 Changeset에 포함됐는지 검증.
- Context 방어 코드가 최종 구조에서 계속 필요한지 검토.
- 전체 STT 자산에 오래된 프로퍼티 이름의 바인딩이 남아 있는지 점검.
- Hanging 진입 중 Holster Montage와 매달리기 손 포즈가 충돌하는지 테스트.
- Aim GA와 Upper StateTree Blueprint 연결 작업 계속 진행.
