# 2026-08-27 일일 개발 리포트

> 집계 시간: 2026-08-27 09:00 ~ 2026-08-28 09:00

## 오늘의 목표

- 무기 종류와 이동·공중·조준·반동 상태를 반영하는 Crosshair HUD 완성
- PlayerHUD 핵심 기능 최종 점검
- 장비·인벤토리·탄약 사용·저장 구조 설계 확정
- 관련 기획·시스템 문서 최신화

## 완료한 작업

### 1. Crosshair 상태 전달 구조 설계

- WeaponComponent에서 무기 손 소지 여부, 무기 종류, 누적 반동 상태를 제공하도록 함.
- Locomotion·Status에서 이동량, 공중 상태, 조준 상태를 제공하도록 함.
- PlayerCharacter가 정보를 종합해 `FPlayerCrosshairState`를 생성하도록 함.
- PlayerController가 Character 이벤트를 구독하고 PlayerHUDComponent로 전달하도록 함.
- PlayerHUDWidget은 최종 표시·숨김, Texture 및 Render Scale만 적용하도록 함.
- 근접무기도 예외 없이 손에 들고 Ready 상태라면 Crosshair를 표시하도록 함.

### 2. 무기 종류별 Crosshair DataAsset 구현

- Crosshair 이미지를 개별 WeaponDataAsset에 중복 저장하지 않고 별도 DataAsset에서 `EWeaponType`별로 관리하도록 함.
- Stable Aim, Unstable Aim, Stable Hip, Unstable Hip, Max Recoil Scale과 보간 속도를 무기 종류별로 정의함.
- Crosshair 표시 조건은 무기가 손에 있고 Carry State가 Ready인 경우로 정함.
- Holstering 진입 시 숨김 상태를 한 번 즉시 발행하도록 함.
- 무기 상태, 이동·공중·조준 및 반동 누적을 기준으로 Crosshair Scale을 선택하도록 함.

### 3. Crosshair C++·Blueprint 연결 수정

- `PlayerCrosshairState`, `WeaponCrosshairDataAsset`과 HUD 전달 코드를 추가함.
- `PlayerHUDComponent.cpp`에서 Crosshair DataAsset 멤버를 사용하기 위한 헤더 누락으로 발생한 C4430·C2143·C4430 연쇄 오류를 수정함.
- `PublishPlayerCrosshairState()`가 Blueprint에서 호출되지 않던 문제를 확인하고 `BlueprintCallable` public 함수로 노출함.
- Tick 실행 순서를 `Update Weapon Runtime → Publish Player Crosshair State`로 정리함.
- Aiming 판정과 현재 무기·Locomotion 상태 조회를 실제 런타임 소유 구조에 맞게 정리함.
- `DA_PlayerHUD`와 `DA_WeaponCrosshair`를 연결하고 `WBP_PlayerHUD.DisplayCrosshair`를 구현함.

### 4. PlayerHUD 핵심 기능 완료

- 체력, 스테미너, 탈진 상태, 무기 아이콘, 현재/최대 탄약을 최종 확인함.
- 무기 수납·Draw에 따른 Crosshair 표시·숨김을 확인함.
- 정지·이동·공중·조준·반동 상태에 따른 Scale 변화를 연결함.
- 무기 종류별 Crosshair Texture와 Scale 설정을 적용함.
- 초기 동기화와 이벤트 기반 갱신이 정상 작동하는 것을 확인함.
- PlayerHUD 핵심 기능을 완료 상태로 판단함.
- Soul Energy는 의도적으로 보류함.

### 5. HUD 잔여 검증 정리

- Holstered, Ready, Holstering, 이동, 점프, Aim, Fire, Recoil Recovery, Reload 상태별 회귀 테스트 항목을 정리함.
- 탄약 미사용 무기의 탄약 UI 숨김과 근접무기 Crosshair 표시를 검증 대상으로 남김.
- 1280×720, 1920×1080, 작은 PIE 창과 울트라와이드에서 Anchor·DPI Scale을 확인하도록 함.
- PlayerHUDDataAsset의 ZOrder가 실제 생성 코드에 적용되지 않는 점을 확인하고 후속 수정 대상으로 남김.
- Hit Marker, 피격 방향, Reload Progress, 탄약 부족 경고 등은 선택 기능으로 분류함.

### 6. 장비 창·인벤토리 기본 구조 확정

- 장비 슬롯을 머리, 몸통, 장갑, 신발, 무기 1·2, 액세서리 1·2, 가방으로 구성함.
- 인벤토리는 7×7 Grid, 기본 7×3인 21칸 사용 가능 구조로 정함.
- 모든 Item 크기는 1×1로 고정함.
- 가방 옵션에 따라 사용 가능 슬롯 수가 늘거나 줄 수 있도록 함.
- 획득한 Equipment는 대응 슬롯이 비어 있으면 Inventory를 거치지 않고 자동 장착하도록 함.
- 대응 슬롯이 가득 차면 Inventory로 이동하도록 함.
- 장비 교체는 기존 장비를 Inventory로 되돌린 뒤 새 장비를 장착하는 원자적 Swap으로 처리함.

### 7. 가방 해제·Compact 규칙 확정

- 가방 해제 시 축소된 활성 슬롯 안으로 Item을 먼저 Compact하도록 함.
- Compact 후에도 넘치는 Item은 Item Bundle 형태의 월드 객체로 생성함.
- 해제한 가방 자체도 같은 Bundle에 포함함.
- Item 이동·장착·해제는 중간 실패로 복제나 손실이 발생하지 않도록 원자적 처리로 설계함.

### 8. 탄약 Reservation과 선호 탄 설계

- 보관되는 탄약 Item과 발사 후 월드에서 이동하는 Projectile Actor를 명확히 분리함.
- 같은 구경에 여러 탄종이 존재할 수 있지만 한 번의 장전에서 탄종을 혼합하지 않도록 함.
- 장전은 Inventory 탄약 수량을 WeaponModel로 직접 옮기는 것이 아니라 사용 가능한 탄약 Stack에 Reservation을 등록하는 개념으로 설계함.
- WeaponModel은 현재 장전 탄종과 Reservation을 기반으로 탄약 사용 권한을 보유하도록 함.
- 선호 탄종은 Player Save Data에 저장하고 Inventory 메뉴에서 지정하도록 함.
- 장전 탄 선택은 현재 Reservation, 선호 탄, 기본 우선순위 순으로 결정하도록 함.
- 선호 탄과 Reserved 탄의 Glow 표현은 같은 탄종 Stack이 여러 개일 때 모호할 수 있어 최종 UI 정책을 보류함.

### 9. ItemModel·EquipmentComponent·저장 구조 설계

- ItemModel을 정적 DataAsset을 참조하는 스마트 런타임 객체로 정의함.
- WeaponModel은 ItemModel 계열의 무기 런타임 상태 객체로 유지함.
- 목표 구조에서는 EquipmentComponent가 장착된 WeaponModel을 관리하고 WeaponComponent는 해당 Model에 행동을 요청하도록 함.
- Item 종류를 Equipment, Ammunition, Ingredient, Miscellaneous로 정리하고 Projectile은 Item이 아닌 월드 공격 Actor로 구분함.
- QuestItem은 폐기가 확정되지 않아 유지함.
- Item GUID를 레벨 간 영속 식별자로 직접 보관하지 않도록 함.
- 레벨 전환 시 SaveData를 기반으로 ItemModel을 새로 생성하고 레벨 단위 Runtime Item ID를 부여하도록 함.
- ItemModel 자체를 저장하지 않고 SaveData로 직렬화하는 구조를 확정함.

## 확정한 설계

- Crosshair는 별도 DataAsset에서 WeaponType별 Texture·Scale을 관리함.
- PlayerCharacter가 Crosshair 상태를 종합하고 HUD 계층은 표현만 담당함.
- PlayerHUD의 핵심 범위는 체력·스테미너·탈진·무기·탄약·Crosshair임.
- Inventory는 7×7 Grid, 기본 21칸, 모든 Item 1×1 구조임.
- Equipment 자동 장착과 Swap은 원자적으로 처리함.
- 가방 해제 시 Compact 후 초과 Item과 가방을 Bundle로 드롭함.
- 탄약은 Ammunition Item이며 WeaponModel에는 혼합되지 않은 단일 탄종 Reservation이 연결됨.
- EquipmentComponent가 장착 Model을 관리하고 WeaponComponent는 실행만 담당하는 방향으로 전환함.
- ItemModel은 SaveData로 직렬화하고 레벨 로드 시 새 런타임 객체와 ID를 생성함.
