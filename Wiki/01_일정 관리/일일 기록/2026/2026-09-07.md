# 2026-09-07 일일 개발 리포트

> 집계 시간: 2026-09-07 09:00 ~ 2026-09-08 09:00

## 오늘의 목표

- 아이템 정의 ID와 런타임 Instance ID의 역할 구분
- CSV에서 DataAsset을 구성하는 정적 데이터 체계 정리
- 탄약·Projectile·Weapon 데이터 연결 보완
- Inventory Tooltip의 UI 데이터 계약 구현
- 게임 기획·시스템 설계·애니메이션 문서를 원문 기준으로 재구성

## 완료한 작업

### 1. 아이템 ID 역할과 명명 규칙 정리

- 여러 CSV 행을 하나의 DataAsset으로 조립하는 키를 런타임 고유 ID와 구분함.
- 정적 정의 조립 키는 `ItemID`, 생성된 ItemInstance 식별자는 Factory가 발급하는 `RuntimeItemId`로 역할을 분리함.
- Gameplay Tag는 개별 Item 식별자가 아니라 탄약 호환성·분류 등 게임 규칙 표현에 사용하도록 함.
- Unreal Asset 이름의 `DA_` 접두어를 ItemID에 포함하지 않는 기준을 정리함.
- Weapon과 Ammunition은 각각 독립적인 ItemID Namespace를 사용하고 Projectile 전용 ID는 제거함.

### 2. CSV·DataAsset 구성 체계 검토

- Item, Equipment, Weapon, Ammunition 및 Weapon 세부 CSV의 책임을 구분함.
- Item 공통 데이터에서 Equipment와 Weapon 세부 데이터로 이어지는 상속·조립 관계를 정리함.
- 동일한 ItemID를 기준으로 WeaponDamage, Fire, Ammo, Accuracy, Aim, Recoil, Charge 및 Continuous 데이터를 하나의 Weapon DataAsset에 구성함.
- 최대 내구도·기본 피해량·발사 설정은 정적 정의에, 현재 내구도·현재 탄약은 Instance에 보관하도록 경계를 유지함.
- 원본 StaticData의 Item·Ammunition CSV 정리 작업과 충돌하지 않도록 문서 변경과 분리함.

### 3. Equipment·Weapon Instance 구조 보완

- EquipmentDataAsset과 EquipmentInstance의 정적·런타임 데이터 경계를 보완함.
- WeaponInstance의 현재 탄약·내구도·탄약 정의 연결을 신규 데이터 체계와 맞춤.
- ItemInstanceFactorySubsystem이 Equipment와 Weapon Instance를 생성할 때 필요한 정의 데이터를 전달하도록 정리함.
- PlayerCharacter, PlayerController와 HUD 계층이 변경된 Item·Weapon 타입을 사용하도록 관련 선언과 연결을 갱신함.

### 4. Ammunition·Projectile 데이터 구조 확장

- AmmunitionDataAsset에 탄종 식별, 비행, Collision, 도탄, 폭발, Homing, 시각 및 Impact 관련 정적 데이터를 정리함.
- AmmunitionInstance가 Inventory 수량과 탄약 정의를 제공하도록 보완함.
- 발사 시 Ammunition 정의가 Projectile Actor에 필요한 데이터를 전달하도록 공격 확정 구조를 갱신함.
- ProjectileActor와 ProjectileFactorySubsystem이 신규 탄약·공격 데이터 구조를 사용하도록 연결함.
- WeaponDataAsset은 사용할 탄약 타입과 무기 설정을 담당하고, 실제 탄환의 비행·Impact 속성은 Ammunition 정의가 담당하도록 경계를 정리함.

### 5. Weapon 발사·재장전 연결 보완

- WeaponComponent가 장착 WeaponInstance와 등록된 AmmunitionDataAsset을 기준으로 발사 데이터를 구성하도록 정리함.
- 탄약 Reservation, 현재 장탄 및 Projectile 생성으로 이어지는 실행 경로를 신규 타입과 맞춤.
- Base Pistol, AR와 9mm 탄약 DataAsset의 필드·참조를 갱신함.
- 탄약 획득 테스트 Blueprint와 Editor Data 설정 Widget을 갱신함.

### 6. Tooltip 전용 ViewData 구현

- `FItemTooltipViewData`를 UI 전용 값 스냅샷으로 추가함.
- Item Name, Icon, Rarity, Quantity, Stack, Weight와 Equipment·Weapon 표시 데이터를 C++에서 조합하도록 함.
- InventoryMenuComponent가 ItemInstance와 각 DataAsset 계층을 해석해 Tooltip ViewData를 생성하도록 함.
- InventoryMenuWidget의 Tooltip Event가 원본 ItemInstance 대신 ViewData를 받도록 변경함.
- Blueprint가 Weapon·Equipment·Ammunition 타입을 직접 Cast하고 원본 객체 구조를 해석하지 않도록 결합을 줄임.
- 현재는 단일 ViewData로 시작하되 데이터가 늘면 Common·Equipment·Weapon·Ammunition 하위 구조체로 분리하는 확장 방향을 정리함.

### 7. Inventory Tooltip Blueprint 연결

- `WBP_InventoryMenu`가 신규 `FItemTooltipViewData`를 받는 흐름을 갱신함.
- Item 종류가 바뀔 때 이전 값이 남지 않도록 매번 새 스냅샷을 구성하도록 함.
- Tooltip은 ViewData를 표시하는 View로 유지하고, 원본 게임플레이 객체 접근은 C++ 중계 계층으로 제한함.

### 8. 게임 기획과 시스템 설계 책임 분리

- `02_게임 기획`은 무엇을 하는지, 규칙·조건·수치와 플레이 경험을 설명하도록 재구성함.
- `03_시스템 설계`는 Unreal Class·Component·StateTree·GAS·데이터 저장과 실행 흐름을 설명하도록 정리함.
- 동일한 규칙을 두 계층에서 중복하지 않고 시스템 설계 문서가 해당 기획 문서를 링크하도록 함.
- 세계관·시나리오·NPC 행동·영혼 결속·이동과 파쿠르 등의 요약 문서에 원본 상세 내용을 복원함.

### 9. 원문·설계·애니메이션 문서 연결 정리

- 기획, 시스템 설계와 애니메이션 설계의 대응 관계를 정리한 표를 갱신함.
- 원본 엑셀과 Markdown 문서의 연결을 위한 원문 대응표를 추가함.
- 시나리오 막별 문서, 캐릭터·세계관 상세, NPC 행동 상세와 시스템 구현 문서를 상호 연결함.
- 기존 애니메이션 문서를 애니메이션 설계 영역으로 정리하고 무기·조준·반동 관련 링크를 갱신함.
- `영혼 결속`, 기획 의도와 설계 의도 표기를 통일하고 근거 없는 의도는 비워둠.

### 10. 문서 전체 검증

- 문서 링크 876개를 검사함.
- 원본 엑셀에서 값이 있는 셀 832개와 Markdown 반영 내용을 대조함.
- 원문 내용과 파일 링크 누락이 없음을 확인함.
- 최상위 제목, 문서 링크, 코드·Mermaid 블록 및 문서 형식을 점검함.
- 완료된 애니메이션 이슈가 미해결로 남아 있던 표현을 정리함.

## 확정한 설계

- ItemID는 정적 Item 정의 조립 키이며 RuntimeItemId는 생성된 Instance 식별자임.
- Gameplay Tag는 Item 고유 ID가 아니라 분류와 호환 규칙을 표현함.
- Ammunition은 Inventory Item이자 발사체 정적 정의, ProjectileActor는 발사 후 월드에서 실행되는 객체임.
- Tooltip에는 원본 객체 대신 C++에서 가공한 `FItemTooltipViewData`를 전달함.
- 게임 기획은 규칙과 경험, 시스템 설계는 Unreal 구현 방법을 설명함.
- 근거가 없는 기획·설계 의도는 문서에 임의로 추가하지 않음.
