# 2026-09-14 일일 개발 리포트

## 오늘의 목표

- EntityStatusModel·PlayerStatusModel 제거와 GAS 소유권 확정
- Player·NPC 공통 Entity ASC 구조 정리 (NPC 제작 선행 조건 충족)

## 완료한 작업

### 1. StatusModel 제거와 ASC 소유권 이관

- EntityStatusModel, PlayerStatusModel 소스 제거
- Character/Pawn이 Entity ASC와 HP·이동·회피·스태미너 AttributeSet을 소유하도록 구조 변경
- PlayerState의 별도 ASC는 플레이어 고유 SoulEnergy만 소유하도록 축소
- NPC가 Possess 해제돼도 NPC ASC의 HP·Effect·쿨다운이 육체에 남는 구조로 정리

### 2. DataAsset 공통 초기화 분리

- DataAsset→Attribute 초기화를 Player와 NPC가 재사용하는 공통 함수 `UEntityAbilitySystemInitializer`로 분리
- DataAsset의 기능 플래그를 Entity ASC의 Capability Tag로 투영하는 `ApplyInitialCapabilityTags` 추가
- Capability Tag 체계 신설 (Movement.Walk/Sprint/Jump/Evade, Combat.Attack/Aim/Reload, SoulLink)

### 3. Authority 확정 변경과 Attribute 제한

- HP·Stamina·SoulEnergy는 Authority에서만 확정 변경하도록 정리
- Max Attribute 감소 시 Current 값도 함께 제한하도록 AttributeSet 수정

### 4. 의미 입력 버퍼와 StateTree 노드 추가

- `UEntityInputBufferComponent` 추가 — PlayerController와 AIController가 만든 의미 입력을 StateTree가 읽고 소비할 수 있게 보관
- Client→Server RPC로 서버 입력 버퍼에도 기록
- StateTree용 입력 확인 Condition(`Has Buffered Entity Input`), 입력 소비 Task(`Consume Buffered Entity Input`), GA 활성화 Task(`Activate Entity Ability By Tag`) 추가

### 5. 로코모션 상태 이전과 Capability 검사

- 회피·파쿠르 런타임 상태와 매달리기 후보를 EntityLocomotionComponent로 이전
- Reload/Attack/Aim에 Capability 검사 추가

### 6. 상태 태그 복제

- State.Dead, State.Resource.Exhausted를 UE 5.8 방식으로 복제

## 확정한 설계

- Entity ASC는 육체(Character/Pawn) 귀속 — NPC와 Player가 동일한 구조 사용
- PlayerState ASC는 SoulEnergy 전용 — Entity Action Ability는 소유하지 않음
- SoulEnergy 비용은 `UAstraEntityGameplayAbilityBase`의 외부 Cost 경계(CanPay/Commit)로 확정 차감
- StateTree 명령은 태그 2개(`StateTree.Event.UpperCommand`, `StateTree.Event.LocomotionCommand`)에 Payload enum(`EUpperStateCommand`, `ELocomotionStateCommand`)으로 구분
- 구 무기 상태 태그(State.Weapon.Holstered/Drawing/Ready/Holstering) 제거 — Holster, ForceHolster는 페이로드 구조체로 사용
- 입력은 Controller가 기록하고 StateTree Condition이 확인, Task가 확정 시점에 한 번 소비
