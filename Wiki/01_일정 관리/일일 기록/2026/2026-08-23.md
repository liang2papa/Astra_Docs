## 완료한 작업

### 1. AimTarget 계산 오류 수정

- 실제 Projectile 시작 위치가 Fire Notify 시점의 Muzzle 소켓 위치임을 확인함.
- 발사 방향은 `고정된 AimTargetLocation - 현재 Muzzle 위치`를 정규화하여 계산함.
- PlayerCameraManager의 Camera Location과 Forward Vector로 만드는 Blueprint Line Trace 흐름을 점검함.
- AimTarget이 비정상 위치에 표시되던 원인이 벡터 연산 괄호 순서였음을 확인함.
- 기존 `(CameraLocation + CameraForwardVector) × EffectiveRange`를 `CameraLocation + (CameraForwardVector × EffectiveRange)`로 수정함.
- Trace 실패 시 HitResult의 Trace End보다 직접 계산한 TraceEnd를 사용하는 구조로 정리함.
- 수정 후 카메라 정면 기준 AimTarget과 `Muzzle → AimTarget` 발사 방향이 정상화됨.

### 2. 발사체 Blueprint Class 구조 수정

- 단일 C++ `AProjectileController`를 생성하면서 `BP_Bullet`의 Scale과 Construction Script가 적용되지 않던 원인을 확인함.
- Unreal의 Actor Blueprint Class가 Unity Prefab에 가까운 실제 생성 단위임을 정리함.
- `AProjectileController`는 공통 실행 코드, `BP_Bullet`은 생성할 실제 발사체 형태, ProjectileDataAsset은 정적 비행 데이터로 역할을 구분함.
- ProjectileDataAsset에 Actor Class를 다시 넣지 않고 현재 장전된 발사체 Blueprint Class를 WeaponModel이 보관하도록 설계함.
- PlayerCharacter의 임시 시작 설정으로 `StartingProjectileActorClass`를 두고 WeaponModel에 주입하도록 함.
- Attack Commit 데이터가 현재 장전된 Projectile Actor Class를 Factory에 전달하도록 변경함.
- ProjectileFactorySubsystem을 발사체 클래스별 Pool로 되돌려 BP_Bullet 등 지정된 Blueprint Class를 생성·재사용하도록 함.
- 사용자 측에서 코드 적용과 빌드를 완료함.

### 3. 권총 잔여 작업 점검

- `BP_PlayerCharacter.StartingProjectileActorClass = BP_Bullet` 설정과 상속 관계를 점검 항목으로 정리함.
- Projectile 발사, 충돌, 탄약 감소 및 같은 클래스 Pool 재사용을 우선 PIE 검증 항목으로 정함.
- `GA_WeaponFire`가 `Event.Weapon.FireFinished`를 실제 Gameplay Event로 수신하는지 확인이 필요함을 기록함.
- AimTarget 디버그 표시 제거, Fire·Reload·Aim 취소 경로, 네트워크 동작 검증을 잔여 항목으로 정리함.
- Rifle, Unarmed, 추가 Projectile 및 발사 방식은 Inventory·Equipment Slot 이후로 미루기로 함.

### 4. 후속 작업 순서 확정

- Draw Montage 제거와 캐릭터 방향 정렬을 우선 처리하기로 함.
- 다음으로 총열과 조준점 방향 보정, Player HUD, 반동과 탄도 분산, 회귀 검증, Gameplay Tag 정리 순서로 진행하기로 함.
- HUD는 반동·확산 검증 전에 작업하여 조준점과 탄약 상태를 시각적으로 확인하도록 함.
- 이동 중에는 조준점 확산과 실제 발사 분산, 정지 초탄은 AimTarget 정확 발사, 후속 사격은 카메라 반동 누적, 입력이 없으면 지연 후 원위치 복귀하는 정책을 정리함.

### 5. Draw 방향 정렬 구현

- Draw Montage만 제거하면 캐릭터가 뒤를 보는 상태에서 발사가 먼저 실행될 수 있음을 확인함.
- `Drawing` 상태와 Pending Action 흐름은 유지하되 캐릭터가 전투 방향으로 정렬된 뒤 손 부착과 Ready 진입을 진행하도록 설계함.
- WeaponComponent에 Player 참조, Tick 또는 Cast를 추가하지 않음.
- `ExecuteDrawWeapon()`은 `bWaitingForDrawAlignment` 상태로 대기하도록 변경함.
- BP_PlayerCharacter가 정렬 완료를 판정하고 `Notify Weapon Draw Alignment Completed`를 호출하도록 함.
- EquipMontage가 없는 권총은 정렬 완료 후 즉시 손에 부착하고, Montage가 있는 다른 무기는 기존 재생 경로를 사용할 수 있도록 함.
- Draw 취소 시 정렬 대기 상태도 함께 초기화함.
- `WeaponDrawAlignmentToleranceYaw` 기본값을 5도로 추가함.

### 6. AimOffset 및 왼손 IK 문제 분석

- 새 `AimOffset_Pistol`의 떨림이 Blend Sample의 Loop 설정 때문에 발생했음을 확인하고 Loop를 꺼 해결함.
- Control Rig와 FABRIK을 일시적으로 제거하여 문제 원인을 AimOffset과 IK 단계로 분리함.
- Pitch 0에서는 왼손이 정확하지만 상하 조준 시 손이 이탈하는 현상을 확인함.
- LeftHandGrip 소켓은 목표 위치를 제공하지만 상체·오른손·총기 포즈가 회전한 뒤 왼손을 다시 고정해야 하므로 적용 순서가 중요함을 정리함.
- AimOffset 샘플 단독 재생과 AnimBP 적용 결과의 차이를 Base Pose, Additive 설정, 중복 AimOffset 및 후처리 노드 관점에서 점검함.

### 7. 총열 방향과 시각 보정 분석

- Muzzle Location과 Muzzle Forward Vector로 총열의 실제 방향을 Debug Arrow로 표시하는 방법을 정리함.
- 검은 선은 총열 방향, 빨간 선은 `Muzzle → AimTarget`, 파란 선은 카메라 Forward 방향으로 구분하여 비교함.
- `DesiredMuzzleRotation`과 Camera Forward Vector의 `Make Rot from X` 결과를 비교함.
- 카메라 Rotation 자체보다 Forward Vector를 Rotator로 변환하는 이유는 실제 발사 방향 벡터와 같은 X축 기준 회전을 얻기 위함임을 정리함.
- 근거리·초근접·중거리·유효 사거리 밖에서 Pitch/Yaw 차이를 측정함.
- 거리별 Parallax Error와 실제 Muzzle Correction을 구분하고 유효 사거리 밖에서는 시각 보정을 비활성화하는 정책을 검토함.
- 총열 보정 후 왼손 IK를 같은 Control Rig에서 순차 적용하는 장기 방향을 정리함.

## 확정한 설계

- AimTarget은 `CameraLocation + CameraForward × EffectiveRange`로 계산함.
- Projectile은 현재 Muzzle 위치에서 고정 AimTarget 방향으로 발사함.
- 생성할 Projectile Blueprint Class는 현재 장전 상태를 소유하는 WeaponModel이 보관함.
- ProjectileFactory는 클래스별 Pool에서 해당 Blueprint Class를 생성·재사용함.
- Draw는 단순 애니메이션이 아니라 캐릭터의 전투 방향 정렬을 보장하는 상태임.
- WeaponComponent는 정렬 대기 상태만 관리하고 실제 회전 판정은 BP_PlayerCharacter가 수행함.
- 총열 시각 정렬과 실제 Projectile 탄도는 분리함.
- 상체·오른손·총기 보정 후 왼손 IK를 마지막에 적용함.
- 이동 사격 확산과 정지 사격 반동은 별도 시스템으로 다룸.
