# 2026-09-03 일일 개발 리포트

> 집계 시간: 2026-09-03 09:00 ~ 2026-09-04 09:00

## 오늘의 목표

- 현재 C++·UI 구현과 기존 장비·인벤토리 설계 차이 확인
- 구현 완료와 PIE 검증 완료 상태 분리
- 설계·로드맵·남은 이슈 문서 최신화

## 완료한 작업

### 1. 기존 설계 대비 구현 차이 정리

- 인벤토리 UI의 C++ 중계 계층인 `UInventoryMenuComponent`와 `UInventoryMenuWidget`이 실제 구현된 상태를 문서에 반영함.
- Stack 분할과 Inventory·Gear Item 드롭 API가 구현된 상태를 반영함.
- WorldItem이 단순 Spawn·Destroy 방식이 아니라 `UWorldItemFactorySubsystem`과 Actor Pool 재사용 구조로 확장된 점을 정리함.
- PlayerController 소유 InventoryMenuComponent와 왼쪽 Gear·오른쪽 7×7 Inventory 화면 구성을 현재 구조로 기록함.

### 2. 구현과 동작 검증 상태 분리

- C++ API와 Widget 에셋이 존재하는 것과 실제 PIE에서 동작이 확인된 것을 별도 상태로 구분함.
- Menu Open/Close, Context 요청과 장비 해제는 확인된 범위로 기록함.
- 장착 슬롯 선택, Stack 분할, Inventory·Gear Drop UI는 검증 대기로 유지함.
- WorldItem Factory·Pool은 구현 상태로 반영하되 Pool 재사용과 부분 획득 전체 회귀 검증은 남김.

### 3. 장비·인벤토리 문서 최신화

- 장비와 인벤토리 문서에 Stack 분할, WorldItem Drop, Pool 준비·취소·재사용 흐름을 추가함.
- Inventory Menu의 View·Controller·Transaction 책임을 현재 C++ 구조에 맞게 정리함.
- 기존 설계 대비 현재 구현 차이를 별도 표로 추가함.
- Ammunition Reservation의 구현 범위와 아직 남은 정책을 재확인함.

### 4. 프로젝트·일정·아키텍처 문서 갱신

- 프로젝트 개요와 로드맵의 장비·인벤토리 진행 상태를 최신화함.
- 남은 이슈에서 완료된 기반 구현과 검증 대기 항목을 분리함.
- 시스템 아키텍처, Player 및 Item 문서에 PlayerController·InventoryMenuComponent·ItemTransfer·WorldItemFactory 관계를 반영함.
- Bag Transaction, SaveData 및 전체 Soft Asset Loading은 미구현 상태로 유지함.

## 확정한 설계

- UI Widget은 표시와 입력 전달만 담당하고 InventoryMenuComponent가 화면 상태를 중재함.
- ItemTransferComponent가 장착·해제·분할·드롭 Transaction을 실행함.
- WorldItemFactorySubsystem이 월드 아이템의 배치와 Pool을 관리함.
- 구현 존재와 PIE 검증 완료는 문서에서 별도로 표시함.

## 테스트·검토 결과

- 관련 설계·상태 문서 7개를 현재 구현과 대조함.
- 깨진 Markdown 링크, Obsidian 전용 링크 및 닫히지 않은 코드·Mermaid 블록이 없음을 확인함.
- 문서 형식 검사를 통과함.
- 장착·분할·드롭 기능은 검증 완료로 과장하지 않고 잔여 이슈로 유지함.

## 잔여 이슈

- 장착 슬롯 선택·Stack 분할·Drop UI PIE 검증.
- WorldItem Pool 재사용 및 부분 획득 회귀 테스트.
- Bag Capacity Transaction과 초과 Item Bundle 처리.
- SaveData 및 ItemInstance 복원.
- Weapon 등 대형 콘텐츠의 Soft Reference 로딩 확대.

■ 프로젝트 개요·로드맵·남은 이슈 최신화  
■ 장비와 인벤토리·Player·Item·시스템 아키텍처 정합성 갱신
