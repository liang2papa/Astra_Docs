# 2026-08-29 일일 개발 리포트

> 집계 시간: 2026-08-29 09:00 ~ 2026-08-30 09:00

## 오늘의 목표

- 장비·인벤토리 초기 구현을 실제 무기와 탄약 흐름에 연결
- 탄약 Item과 Projectile 실행 객체의 책임 분리
- WorldItem 기반 필드 획득 및 부분 이동 구현
- 무기 재장전 진입 문제 진단
- 현재 C++ 구현에 맞춰 Astra 문서 전반 최신화

## 완료한 작업

### 1. Entity 상태 중재 구조 정리

- Entity State Event Type과 Event Bus 구조를 정리함.
- EntityStateMediatorComponent의 명령·상태 전달 흐름을 보완함.
- 전투 상태와 연동하는 Gameplay Tag 등록·초기화 구조를 정리함.
- EntityContext와 ControllableEntity의 상태 중재 참조를 현재 구조에 맞게 조정함.
- EntityHealthComponent가 상태 이벤트 계층과 연결되는 구간을 정리함.

### 2. 장비 소유 구조를 GearComponent로 확정

- 기존 설계상의 EquipmentComponent를 실제 구현명인 `UGearComponent`로 정리함.
- PlayerState가 InventoryComponent와 GearComponent를 소유하도록 구성함.
- 장비 슬롯 타입과 EquipmentDataAsset의 장착 슬롯 정의를 정리함.
- 장착·해제·자동 장착 및 WeaponInstance 접근 흐름을 GearComponent 기준으로 연결함.
- PlayerCharacter와 WeaponComponent가 PlayerState 소유 장비·인벤토리 참조를 사용하도록 조정함.

### 3. Ammunition Item 계층 구현

- `UAmmunitionDataAsset`과 `UAmmunitionInstance`를 추가함.
- 보관·획득·장전되는 탄약 Item과 월드에서 발사되는 Projectile Actor를 별도 객체로 분리함.
- 탄약 DataAsset이 탄종 정보와 발사에 필요한 Projectile Data를 참조하도록 구성함.
- ItemInstanceFactorySubsystem이 Ammunition DataAsset에 맞는 AmmunitionInstance를 생성하도록 확장함.
- WeaponDataAsset·WeaponInstance와 탄약 정의의 연결을 정리함.

### 4. 탄약 Reservation과 Reload 연동 구현

- Inventory가 탄약의 전체 수량, 예약 수량, 사용 가능한 수량을 구분하도록 함.
- WeaponInstance가 현재 장전 탄종과 Reservation 정보를 관리하도록 연결함.
- GearComponent가 장착된 무기에 Inventory 탄약을 등록하는 흐름을 추가함.
- Reload 시 탄창 부족량과 사용 가능한 탄약을 기준으로 탄약을 선택·예약·소비하도록 구현함.
- 탄창 탄약과 Inventory 예비 탄약의 HUD 전달 경로를 현재 구조에 맞게 정리함.
- 같은 탄종의 Inventory 수량이 탄창 Reservation으로 모두 잡힌 경우 추가 장전 가능 수량이 0이 되는 동작을 확인함.

### 5. Projectile 구조 최신화

- Projectile 실행 객체를 현재 구현명인 `AProjectileActor` 기준으로 정리함.
- ProjectileDataAsset과 ProjectileFactorySubsystem의 타입·생성·풀링 연결을 보완함.
- Weapon 공격 확정 데이터가 탄약의 Projectile Data를 전달하도록 조정함.
- CombatEffectSubsystem과 PlayerCharacter의 발사·효과 전달 타입을 신규 구조에 맞게 정리함.

### 6. WorldItem 번들 구조 구현

- `AWorldItemActor` 하나가 여러 `UItemInstance`를 담을 수 있는 최소 Item Bundle로 동작하도록 구현함.
- 배치 시 지정한 ItemDataAsset과 수량을 MaxStackSize 기준의 ItemInstance들로 생성하도록 함.
- 플레이어 Collision Overlap 시 PlayerState의 ItemTransfer·Inventory로 자동 획득을 요청하도록 함.
- Inventory가 수용 가능한 수량만 이동하고 남은 수량은 WorldItem에 유지하도록 함.
- 모든 Item이 이동된 경우에만 WorldItem Actor를 제거하도록 함.
- 여러 Item이 들어 있는 경우 배열 순서대로 이동을 시도하고, 하나라도 남으면 Actor와 Collision을 유지하도록 함.

### 7. 부분 Stack 이동 API 구현

- InventoryComponent에 외부 ItemInstance의 수용 가능 수량만 이동하는 API를 추가함.
- 기존 동일 Stack의 빈 공간을 먼저 채우고 남은 수량은 빈 Slot에 저장하도록 함.
- Inventory가 일부만 수용할 수 있으면 이동된 수량만 원본에서 차감하고 나머지를 WorldItem에 유지하도록 함.
- Equipment는 전체 이동만 허용하고 Stack Item은 일부 수량 이동이 가능하도록 ItemTransferComponent 경계를 정리함.
- 이동된 Slot과 탄약 수량 변경 이벤트가 HUD·후속 시스템에 전달되도록 함.

### 8. WorldItem 표시 Mesh 비동기 로딩 구현

- ItemDataAsset의 Static Mesh를 Soft Reference로 두고 런타임에 비동기 로드하도록 함.
- `FStreamableHandle`로 진행 중인 로딩 작업을 추적·취소하도록 구성함.
- WorldItem이 제거되거나 표시 대상이 바뀌면 기존 로딩 Handle을 취소하도록 함.
- 로딩 완료 시 요청 경로가 현재 표시 대상과 일치하는지 확인한 뒤 Mesh를 적용하도록 함.
- 에디터 배치 미리보기와 런타임 비동기 로딩의 역할을 분리함.
- `FStreamableHandle` 전방 선언을 실제 `struct` 정의와 일치시키고 필요한 StreamableManager 헤더를 포함함.

### 9. Reload 불가 현상 원인 분리

- 탄창에 탄약이 남아 있을 때 Reload가 되지 않는 현상을 추적함.
- C++의 부분 장전 조건은 `CurrentAmmo < MaxLoadedAmmo`로 정상이며, 예비 탄약이 모두 Reservation 상태라 사용 가능 수량이 0이면 추가 Reload가 거부되는 것이 정상임을 확인함.
- 총을 내린 상태에서는 Reload되지만 Ready 상태에서 진입하지 않는 별도 문제를 분석함.
- `BP_PlayerCharacter`의 Reload 입력이 신규 `RequestWeaponReload()`을 사용하지 않고 기존 Carry State 분기와 Upper Command 경로를 우회하는 것이 원인임을 확인함.
- Reload 입력을 `IA_Astra_Reload.Started → WeaponComponent.RequestWeaponReload` 단일 경로로 연결하는 수정안을 정리함.
- Fire Montage 진행 중 입력을 예약 실행하는 정책은 별도 입력 버퍼 작업으로 남김.

### 10. WeaponComponent 책임 분산 방향 정리

- 인벤토리·탄약 Reservation을 먼저 완성한 뒤 WeaponComponent를 분해하는 순서를 유지함.
- 최종 실행 의존 방향을 `STT → GA → WeaponComponent`로 정리함.
- STC는 진입 조건을 읽기 전용으로 조합하고, GA는 Montage·Notify·Commit·취소·완료 수명을 담당하도록 구분함.
- InventoryComponent는 예비 탄약 검색·예약·확정·해제를 담당하고 WeaponInstance는 탄창 수량을 담당하도록 함.
- WeaponComponent에는 현재 장착 무기, Carry, Draw/Holster, Aim Solution, Muzzle 및 Commit용 기능을 남기는 방향을 유지함.

### 11. 기획·시스템 문서 전반 최신화

- 설계 용어인 ItemModel·WeaponModel을 실제 `UItemInstance`·`UWeaponInstance` 구현명으로 교체함.
- EquipmentComponent를 실제 `UGearComponent` 구조로 최신화함.
- PlayerState 소유 Inventory·Gear·ItemTransfer 구조를 관련 문서에 반영함.
- 탄약 Reservation·선호 탄종·Reload 연동과 WorldItem 부분 획득 구조를 문서화함.
- Projectile 실행 객체를 `AProjectileActor`로 수정함.
- 프로젝트 개요, 로드맵, 남은 이슈, 장비와 인벤토리, Item, Player, 무기 시스템, 시스템 아키텍처, 개발·작업 규칙 및 ADR을 현재 코드와 맞춤.
- SaveData, Bag Capacity Transaction, UI, 전체 Soft Asset 로딩은 미구현 상태로 유지함.

## 확정한 설계

- 실제 구현 용어는 `UItemInstance`, `UWeaponInstance`, `UGearComponent`를 사용함.
- PlayerState가 Inventory·Gear·ItemTransfer를 소유함.
- 탄약 Item은 AmmunitionInstance이며 ProjectileActor와 분리함.
- Inventory가 Reservation을 소유하고 WeaponInstance는 탄창과 현재 탄종을 소유함.
- WorldItem은 단일 Item이 아니라 복수 ItemInstance를 담을 수 있는 최소 Bundle임.
- WorldItem 획득은 가능한 수량만 이동하고 초과 수량은 월드에 유지함.
- 무기 행동의 최종 실행 구조는 `STC → STT → GA → WeaponComponent/Inventory/WeaponInstance` 방향임.
