# 2026-08-20 일일 개발 리포트

> 집계 시간: 2026-08-20 09:00 ~ 2026-08-21 09:00

## 오늘의 목표

- GA가 PlayerController를 반복 탐색하지 않도록 Aim 카메라 참조 구조 개선
- 혼재된 콘텐츠 에셋을 책임과 객체 분류 기준으로 재정리
- 확정된 시스템 구조와 게임 객체 분류를 기획·설계 문서에 반영

## 완료한 작업

### 1. Aim 카메라 참조 구조 개선

- `AAstraPlayerState`가 Ability System Component를 소유하고 PlayerCharacter가 AvatarActor로 연결되는 관계를 재확인함.
- PlayerController가 PlayerCameraManager를 생성·관리하며 PlayerCharacter는 Possess된 Pawn이라는 Gameplay Framework 관계를 정리함.
- GA 활성화 때마다 Avatar → Controller → PlayerCameraManager 캐스팅을 반복하는 방식을 폐기함.
- PlayerCharacter가 `PossessedBy`, `PawnClientRestart`, `OnRep_PlayerState`, `BeginPlay` 시점에 PlayerCameraManager를 확인해 `EntityContext`에 등록하도록 구현함.
- `UnPossessed`에서는 EntityContext의 PlayerCameraManager 참조를 제거하도록 함.
- `UAstraWeaponGameplayAbilityBase`를 추가하고 `OnAvatarSet`에서 AvatarActor의 EntityContext만 저장하도록 구현함.
- `StartAimCameraFOV`, `StopAimCameraFOV` Blueprint 호출 함수를 Ability 기반 클래스에 추가함.
- 변경 후 UE 5.8 `Astra_SoulLinkEditor Win64 Development` 빌드 성공 및 인게임 정상 실행을 확인함.

### 2. GameMode·Possess·Ability 초기화 흐름 정리

- 맵의 World Settings에서 `BP_GameMode`가 선택되고 Default Pawn Class와 Player Controller Class가 적용되는 위치를 확인함.
- `AGameModeBase`가 PlayerController, PlayerState, 기본 Pawn을 생성하고 PlayerController가 Pawn을 Possess하는 엔진 흐름을 정리함.
- Ability 인스턴스가 스스로 `OnAvatarSet`을 실행하는 것이 아니라 ASC의 `GiveAbility` 및 `InitAbilityActorInfo` 흐름에서 호출된다는 점을 명확히 함.
- `OnAvatarSet`은 Ability 활성화마다 실행되는 함수가 아니라 AvatarActor가 지정되거나 변경될 때 호출되는 초기화 지점으로 정리함.

### 3. 콘텐츠 객체 분류 확정

- 최상위 게임 객체 분류를 `Entity / Item / Prop`으로 확정함.
- Entity를 고유한 상태를 가지며 판단 또는 명령에 따라 행동 주체로 작동하는 객체로 정의함.
- Entity 하위 유형을 Player, NPC, Structure로 구분하고 Structure Entity와 단순 환경 Prop의 판단 기준을 정리함.
- Item을 획득·소유·보관·이전 가능한 객체로 정의하고 Equipment를 Item의 하위 유형으로 배치함.
- Item 종류를 `Equipment / Projectile / Ingredient / QuestItem / Miscellaneous`로 확정함.
- `Consumable`과 `Crafting`은 서로 겹칠 수 있으므로 폴더 종류가 아니라 사용 속성 또는 Gameplay Tag로 표현하기로 함.
- Unreal 렌더링 `Material`과 혼동되지 않도록 Item 분류에서 Material 명칭을 제거함.
- Interactable, Damageable, Shop, Craftable 등은 객체 정체성이 아니라 Capability로 분리함.

### 4. 콘텐츠 폴더 구조 및 Readme 규칙 설계

- Player 폴더에 섞여 있던 플레이어 전용, 인간형 Entity 공용, 무기 관련 에셋을 책임별로 분리하는 구조를 제안함.
- 인간형 공용 애니메이션과 StateTree는 Unreal 템플릿 `Characters/Mannequins`가 아니라 `Astra/Entity/Humanoid` 아래에 두기로 함.
- Player 전용 Blueprint·Camera·Data, Humanoid 공용 Locomotion·Animation, Item/Equipment/Weapon 관련 Ability·StateTree를 구분함.
- Content Browser에는 폴더 설명을 직접 표시하는 기본 기능이 없으므로 폴더별 Readme Data Asset을 두는 방식을 정리함.
- Readme 필드를 `Title`, `Definition`, `IncludedTypes`, `ExcludedTypes`, `Subfolders`, `Examples`, `LastUpdated` 중심으로 단순화함.
- 반복되는 전역 네이밍 규칙은 폴더별 Readme가 아니라 별도 공통 문서에 두기로 함.
- Entity와 Input 폴더에 들어갈 ExcludedTypes, Subfolders, Examples 작성 기준을 정리함.

### 5. 문서 저장소 현행화

- 상세 문서 38개에 상위 페이지와 관련 문서 탐색 링크를 추가함.
- 시스템 설계 허브에 GameMode, PlayerController, PlayerState, Pawn, PlayerCameraManager, EntityContext 관계를 반영함.
- `UAstraWeaponGameplayAbilityBase`, EntityContext를 통한 카메라 참조, Aim Hold/Toggle, STC/STT/GA 실행 흐름을 시스템 문서에 추가함.
- `PlayerCameraManager 참조 구성.md`를 추가해 재사용 가능한 Unreal 일반 지식으로 분리함.
- `게임 객체 분류.md`를 추가하고 Entity, Item, Prop, Capability 및 콘텐츠 폴더 구조를 시각화함.
- 최신 합의에 따라 Item 분류와 Crafting/Consumable 속성 체계를 문서에 갱신함.
- Wiki 링크와 문서 형식 검사를 통과함.

### 6. 에셋 이동 후 Blueprint 오류 분석

- 폴더 이동 중 `Resolve Weapon Component`의 `SetCurrentAvatar`가 None으로 보이던 문제를 분석함.
- 실제 원인은 값 전달 실패가 아니라 `GA_WeaponBase`와 자식 GA의 SkeletonGeneratedClass 및 부모 프로퍼티 구조 불일치였음을 확인함.
- Redirector 정리 후 에디터 재시작, 부모 `GA_WeaponBase`부터 자식 GA와 Player Blueprint 순서로 `Refresh All Nodes → Compile → Save`하는 복구 절차를 정리함.

## 확정한 설계

- PlayerCameraManager 참조는 PlayerCharacter가 Controller 연결 시점에 한 번 확인해 EntityContext에 등록함.
- Gameplay Ability는 PlayerController를 직접 탐색하지 않고 Avatar의 EntityContext를 참조 경계로 사용함.
- 최상위 게임 객체는 `Entity / Item / Prop`으로 분류하고 중복 가능한 성질은 Capability 또는 Gameplay Tag로 표현함.
- Equipment는 Item의 하위 유형이며 Weapon과 Projectile은 서로 다른 Item 종류로 관리함.
- 인간형 공용 에셋은 템플릿 Mannequin 폴더와 분리해 Astra의 `Entity/Humanoid` 영역에 둠.
- 콘텐츠 폴더 설명은 Readme Data Asset과 Wiki 문서를 함께 사용함.
