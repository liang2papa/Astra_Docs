# 로드맵과 완료 기준

## 2. 완료된 핵심 작업

### 로코모션

- Walk, Sprint, Jump, Falling, Evade
- 어깨 폭과 정면 조건을 포함한 Hanging
- Root Motion + Motion Warping Mantle
- Mantle 후 Falling/재매달림/중력 복구
- Vault 상태와 이동 취소 함수

### 무기

- 권총 Static Mesh 장착
- WeaponDataAsset / WeaponInstance / WeaponComponent 책임 분리
- 손/홀스터/Muzzle Socket
- Draw/Holster Montage와 Notify
- Upper StateTree에 Carry와 Action 통합
- 자동 Holster Timer
- C++ `UAstraWeaponGameplayAbilityBase`와 Blueprint `GA_WeaponFire`, `GA_WeaponReload`, `GA_WeaponAim`
- 카메라 Ray 목표와 Muzzle 기반 Projectile 방향 수정
- Fire/Aim 진입 시 Sprint 취소 정책
- Fire Montage와 `Weapon_FireCommit` Notify 기반 실제 발사
- `GA_WeaponReload`, `STC_CanReload`, `STT_WeaponReload`
- Reload Montage와 `Weapon_ReloadCommit` Notify 기반 탄약 반영
- Sprint·Holster 중 Reload 취소와 Ready 복귀
- 카메라 Pitch ±70 제한과 Aim Offset 보간
- `LeftHandGrip` Socket과 FABRIK 연결
- Aim Hold/Toggle 입력, `STC_CanAim`, `STT_WeaponAim`, `GA_WeaponAim` 연결
- EntityContext 기반 PlayerCameraManager 참조와 Aim FOV 진입·복귀

### 아키텍처

- AstraPlayerState에 ASC와 AttributeSet 배치
- EntityStateMediatorComponent 이벤트 허브
- Base/Upper StateTree 간 GameplayTag 이벤트 중재
- EntityContext에 ASC, Health, Mediator, EventBus 참조 추가

### 장비·인벤토리

- `UItemDataAsset`과 ItemInstance·AmmunitionInstance·EquipmentInstance·WeaponInstance 계층
- World 단위 `UItemInstanceFactorySubsystem`과 Runtime Item ID 발급
- PlayerState 소유 InventoryComponent·GearComponent·ItemTransferComponent
- 49 Slot, 기본 Capacity 21, Stack 이동·병합·분할, Compact와 탄약 수량 이벤트
- 장비 Slot 호환성, 자동 장착, Inventory↔Gear Swap·Unequip Rollback
- WeaponInstance Runtime ID별 탄약 Reservation, 선호 탄종과 선택 우선순위
- WeaponComponent의 Inventory Reservation 소비·Reload 연동
- 복수 ItemInstance Bundle인 WorldItemActor와 수용 가능한 수량만 부분 획득
- WorldItemFactorySubsystem의 전방 지면 Drop, 준비·취소 Transaction과 Actor Pool
- Inventory·Gear 전체 Item Drop API, Reservation을 침범하는 탄약 Drop과 Bag Drop 차단
- PlayerController 소유 InventoryMenuComponent와 InventoryMenuWidget Blueprint 이벤트 경계
- Inventory/Gear Slot·아이콘·Context Menu Blueprint 구성과 장비 해제 경로 확인
- ItemID 기반 Item·Equipment·Weapon·Ammunition CSV Import
- Weapon 수치의 9개 CSV 분리와 `CsvSource` Header 검증
- Projectile 정적 정의의 AmmunitionDataAsset 통합
- EquipmentDataAsset·EquipmentInstance 공통 내구도와 파손 사용 차단
- `FItemTooltipViewData` 기반 Tooltip 표시 계약
- 2026-09-08 Development Editor / Win64 빌드 성공

## 3. 현재 최우선 작업

작업별 우선순위와 선행 관계를 함께 적용한다.

1. EntityLocomotionComponent 책임 분할 설계와 구현
2. EntityStatusModel의 AttributeSet 이전과 제거
3. 위 구조 정리 후 적대 인간형 NPC 제작
4. 무기 해제 후 재장착 시 발사 불가 수정
5. 총기 명중률의 실제 ShotDirection 연결

최근 구조 반영:

- WeaponComponent의 Aim·Carry·Reload·Recoil·AttackSequence·AttackCommit Handler 분리
- WeaponComponent Facade와 FWeaponHandlerContext 구성
- Weapon1·Weapon2 선택과 빈 슬롯 맨손 전환
- RapidFire·Continuous 반복 공격 Sequence
- AttackCommitHandler의 PhysicalProjectile·Hitscan·Beam 전달

세부 우선순위와 후순위 개선은 [남은 이슈](%EB%82%A8%EC%9D%80%20%EC%9D%B4%EC%8A%88.md)에서 관리한다.

## 4. 미결정·보류 항목

- Vault 전용 애니메이션과 최종 이동 방식
- 무기별 Anim Layer 구조의 확장 시점
- 표면 재질별 Projectile Impact VFX/Sound
- NPC ASC의 정확한 소유 클래스
- Bag 장착·해제 시 Capacity 감소와 초과 WorldItem 배치 방식
- SaveData Schema와 ItemInstance 복원 구현
- Preferred/Reserved 탄약 대표 Stack UI 표현
- WeaponInstance 장전 탄약과 Inventory Reservation의 동기화·Drop 규칙
- EntityLocomotionComponent의 세부 Handler와 클래스 경계
- WorldItem의 ItemStaticMesh Soft Reference 로딩 정책
- Soul-Link AbilitySet 교체 방식과 NPC AI/Player Control 공존 규칙

## 5. 완료 정의

기능은 다음을 모두 만족해야 완료로 기록합니다.

- 정상 경로가 동작함
- 실패·중단·사망 경로에서 상태가 복구됨
- StateTree, GAS, Component 중 단일 소유권이 명확함
- Blueprint 런타임 None 오류가 없음
- 에디터 종료 시 AnimGraph/Delegate 경고가 없음
- 로그와 플레이 테스트 결과가 일일 리포트에 기록됨
