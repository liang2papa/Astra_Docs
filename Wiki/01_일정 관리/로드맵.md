# 로드맵과 완료 기준

> 최종 갱신: 2026-10-26 (공통 실행 기반·소환기 C++ 반영, 사용자 에셋 연결/빌드·PIE 대기)
> 현재 구조·근거·재개 순서는 [현재 작업 상태와 재개 기준](현재%20작업%20상태.md) 참조. 과거 사용자 확인과 이후 수정의 검증 대기를 구분
> 최신 사용자 지정: **보스 → 아스트라**. 보스 스킬에 공통 실행 기반을 먼저 적용하고 영혼 결속은 아스트라 제작 시 구현. 기존 단계 번호는 관리 분류이며 날짜·전체 일정 재산정과 구분.

## 2. 완료된 핵심 작업

### 로코모션

- Walk, Sprint, Jump, Falling, Evade
- 어깨 폭과 정면 조건을 포함한 Hanging
- Root Motion + Motion Warping Mantle
- Mantle 후 Falling/재매달림/중력 복구
- Vault 상태와 이동 취소 함수

### 무기

- 권총 Static Mesh 장착
- WeaponDataAsset / WeaponInstance / WeaponComponent 책임 분리
- 손/홀스터/Muzzle Socket
- Draw/Holster Montage와 Notify
- Upper StateTree에 Carry와 Action 통합
- 자동 Holster Timer
- C++ `UAstraWeaponGameplayAbilityBase`와 Blueprint `GA_WeaponFire`, `GA_WeaponReload`, `GA_WeaponAim`
- 카메라 Ray 목표와 Muzzle 기반 Projectile 방향 수정
- Fire/Aim 진입 시 Sprint 취소 정책
- Fire Montage와 `Weapon_FireCommit` Notify 기반 실제 발사
- `GA_WeaponReload`, `STC_CanReload`, `STT_WeaponReload`
- Reload Montage 정상 종료 시 탄약 반영. Weapon_ReloadCommit Notify 확정 방식 대체
- Sprint·Holster 중 Reload 취소와 Ready 복귀
- 카메라 Pitch ±70 제한과 Aim Offset 보간
- `LeftHandGrip` Socket과 FABRIK 연결
- Aim Hold/Toggle 입력, `STC_CanAim`, `STT_WeaponAim`, `GA_WeaponAim` 연결
- EntityContext 기반 PlayerCameraManager 참조와 Aim FOV 진입·복귀

### 아키텍처

- Entity ASC의 육체 귀속 이관 — Character/Pawn이 HP·이동·회피·스태미너 AttributeSet과 Entity ASC를 소유
- AstraPlayerState는 SoulEnergy 전용 ASC와 PlayerAttributeSet, Inventory·Gear·ItemTransfer 소유. 현재 EntitySoulEnergyComponent는 PlayerCharacter 소유이며 자원 ASC 연결 보완은 [영혼 결속](../03_시스템%20설계/영혼%20결속.md) 참조
- EntityStatusModel·PlayerStatusModel 제거 — 능력치는 AttributeSet과 GameplayTag가 소유
- DataAsset→Attribute 초기화를 Player·NPC 공통 함수 `UEntityAbilitySystemInitializer`로 분리
- Capability Tag 체계 추가 — DataAsset 기능 플래그를 Entity ASC에 투영
- Authority에서만 HP·Stamina·SoulEnergy 확정 변경, Max 감소 시 Current 함께 제한
- EntityStateMediatorComponent 이벤트 허브
- Base/Upper StateTree 간 타입이 지정된 Payload 명령 중재 (EUpperStateCommand / ELocomotionStateCommand)
- EntityContext에 ASC, Health, Mediator, EventBus, InputBuffer 참조
- Entity 의미 입력 버퍼(UEntityInputBufferComponent)와 Client→Server RPC 추가
- StateTree 입력 확인 Condition, 입력 소비 Task, GA 활성화 Task C++ 노드 추가
- 회피·파쿠르 런타임 상태와 매달리기 후보를 EntityLocomotionComponent로 이전
- Reload/Attack/Aim에 Capability 검사 추가
- State.Dead, State.Resource.Exhausted를 UE 5.8 방식으로 복제
- EntityStaminaAttributeSet 비용·회복 Attribute 추가 (Evade/Sprint/Jump 비용, ExhaustRecoveryRatio)
- `IControllableEntity` 공통 제어 인터페이스와 `EEntityControlCommand` 신설 (2026-09-16)
- `UEntitySoulEnergyComponent` 신설 — SoulEnergy CanPay/CommitCost와 회복 지연. 수치 원본은 PlayerState ASC (2026-09-16)
- 의미 입력 버퍼에 Pulse 입력·MoveInput·서버 RPC 확장 (2026-09-16)
- Locomotion 상태 이벤트(Sprint/Airborne/Traversal/Evade 진입)의 EventBus 발행과 EntityContext 구독 (2026-09-16)
- EntityDataAsset Capability 플래그 확장 — bCanAim, bCanReload, bCanSoulLink (2026-09-16)
- EntityLocomotionComponent Blueprint 계약 확정 — 카테고리 체계, PendingLedge·PendingParkour 캐시, OnMantleFinished (2026-09-16)
- Sprint 토글 의도를 입력층(PlayerCharacter)이 소유 — CancelSprint 경유 시 클리어, JumpStart 경유 시 유지. 탈진 후 자동 재달리기 없음 (2026-09-16)
- 스태미너 부분 소모 경계(bAllowPartialSpend) 추가 — 일회성 비용과 초당 소모 구분 (2026-09-17)
- 조준 FOV 제어를 Weapon GA C++ 경로로 이관하는 기반 추가 (2026-09-18)
- 발사체 발사 방향을 ShotDirection 기반으로 전환과 명중률·퍼짐 계산 API 추가 (2026-09-18)
- STT Blueprint는 호출 순서만, C++ 컴포넌트가 태그·몽타주·물리를 소유하는 일관성 규칙 확정 (2026-09-16)
- 2026-09-16, 2026-09-18 Development Editor / Win64 빌드 성공

## 3. 현재 최우선 작업

2026-10-21 사용자 완료 확인 반영. 다음 착수 제안과 기존 잔여 분리

1. PT-00-3은 사용자 패스. 이번 애니메이션 수정 후 다수 증상 해소, 현재 선행 작업에서 제외
2. 다음 착수 제안은 PT-00-5 아스트라·보스 기본 제작. 공통 Entity 구성과 보스 모델·모션 호환부터 확인
3. 해결된 사망 경로는 유지, 세부 포즈 미확인 범위는 후속 QA로 분리. 아스트라·보스 기본 제작 → 보스 인카운터 설계 순서 유지
4. 연사·반동·교체 후 발사·DamageLook 종료 로그는 별도 잔여 유지. 추적·재장전은 완료 상태로 유지

최신 C++ 반영과 사용자 Editor 연결 대기, 기존 로그의 검증 범위는 [현재 작업 상태](현재%20작업%20상태.md)와 [플레이어 연결 안내](../07_QA_테스트/플레이어%20연사·빈%20탄창%20재장전%20연결.md)에 기록한다. Lyra·라이플 확보와 사용자 확인된 AO 참조 수정은 완료 상태 유지.

### 기존 NPC 후속 작업의 갱신 — 2026-10-21

기존 10/08 생성·연결 백로그를 최신 제공 트리와 사용자 확인으로 갱신. 현재 착수 순서와 구분

1. NPCBrain Idle Command·Base Patrol·ChaseWalk·DamageLook 배치와 바인딩은 제공 트리에서 확인. 새 Task 생성 대기로 분류하지 않음
2. 추적·재장전은 사용자 완료 확인. 사거리 이탈·Patrol 잔류 진단 종결
3. 사망 전이 문제 해결·우선권 상향 사용자 확인. 공통 사망 경로 유지
4. 순찰 시선은 PT-00-3 사용자 패스로 현재 범위 제외. 과거 DamageLook 종료 참조·전리품 세부 동작은 개별 잔여로 분리

최근 반영: 반복 공격·몸 방향 정렬·NPC 탄창 소비와 무제한 예비 재장전, 마지막 확인 위치 기억·이동·탐색 대기, 취소 후 발사 쿨다운 유지

사격·재장전의 과거 확인과 추적·재장전의 최신 완료 지정 구분. Debug Text 표시만으로 실제 Brain 종료 판단 금지

NPC 연결·회귀 항목은 [QA 목록](../07_QA_%ED%85%8C%EC%8A%A4%ED%8A%B8/07_QA_%ED%85%8C%EC%8A%A4%ED%8A%B8.md) 참조

### 기존 후속 작업

작업별 우선순위와 선행 관계를 함께 적용한다.

1. GA_Evade, GA_Sprint, GA_Jump와 Cost/Effect 에셋 구성
2. Blueprint/StateTree 에셋 25개 재연결 (에디터 작업)
3. NPC 전리품 등 개별 잔여. 추적·재장전·사망 전이는 완료 유지, PT-00-3 시선 작업은 사용자 패스
4. 영혼 결속 실제 Possess/해제 구현
5. AbilitySet 기반 부여 구조
6. EntityLocomotionComponent 세부 분할 — Blueprint 계약·C++ 인터페이스 반영 완료 (2026-09-16). 세부 Handler 분할 여부 검토
7. 무기 해제 후 재장착 시 발사 불가 수정
8. 총기 명중률의 실제 ShotDirection 연결

최근 구조 반영:

- WeaponComponent의 Aim·Carry·Reload·Recoil·AttackSequence·AttackCommit Handler 분리
- WeaponComponent Facade와 FWeaponHandlerContext 구성
- Weapon1·Weapon2 선택과 빈 슬롯 맨손 전환
- RapidFire·Continuous 반복 공격 Sequence
- AttackCommitHandler의 PhysicalProjectile·Hitscan·Beam 전달

세부 우선순위와 후순위 개선은 [남은 이슈](%EB%82%A8%EC%9D%80%20%EC%9D%B4%EC%8A%88.md)에서 관리한다.
