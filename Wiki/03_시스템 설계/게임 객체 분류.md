# 게임 객체 분류

## 설계 의도

기획의 객체 정체성과 구현 책임을 일치

## Entity 행동과 Weapon Item의 책임

무기를 사용하는 행동은 Entity가 소유하고, 사용되는 무기의 내부 상태와 결과는 Weapon Item이 소유

| Entity가 소유 | Weapon Item이 소유 |
|---|---|
| 행동 가능 여부 | 무기 종류와 정적 데이터 |
| 입력·AI 명령 해석 | 현재 탄창과 예비 탄약 연계 상태 |
| 조준·발사·재장전 행동 | 탄창 크기와 탄약 증감 결과 |
| 상·하체 행동 StateTree | 발사 간격과 발사 방식 |
| GA 활성화·취소 | 피해·사거리·탄속 |
| 행동 충돌 정책 | 반동·탄 퍼짐 |
| 행동 애니메이션 | Muzzle, Projectile, 과열·고장·내구도 |

`GA_WeaponAim`, `GA_WeaponFire`, `GA_WeaponReload`이라는 이름은 Weapon Item이 Ability를 소유한다는 뜻이 아니다

**Entity가 Weapon Item을 사용하는 행동**을 뜻

재장전은 양쪽 책임이 만나는 대표 사례다

- Entity: Reload 행동 진입, 애니메이션, 이동·다른 행동 제한, 탄약 이전 요청
- Weapon Item: 현재 탄약, 최대 탄창, 실제 탄약 반영 결과

공용 여부는 “AI 인간형이 같은 Ability를 받아 정상 사용할 수 있는가?”로 판단

- 가능함: Humanoid Entity 공용 행동
- 플레이어 입력이나 카메라에 의존함: Player Entity 전용 행동

현재 `UAstraWeaponGameplayAbilityBase`에는 플레이어 카메라 FOV 의존성이 있으므로 완전한 Humanoid 공용 기반으로 보지 않음

NPC와 공유하려면 카메라 정책을 분리하거나 인터페이스 경계로 격리한 뒤 승격

```text

├─ Entity/
│  ├─ Common/

│  │  ├─ Data/
```

`Input`과 `Levels`는 객체 종류가 아니라 별도의 시스템·콘텐츠 폴더

인간형 공용 애니메이션과 StateTree는 Player나 Weapon 아래가 아니라 `Entity/Humanoid`에 둠

Epic 템플릿 원본은 Mannequins에 보존하고, Astra에서 재사용할 복사본만 Humanoid 영역으로 이동

에셋 폴더는 실제 재사용이 확인될 때 세분화

이동은 Unreal Content Browser에서 수행하고 Redirector 정리와 Reference Viewer 검증을 수행

## 속성 표현

```text
Item.Usage.Equipable
Item.Usage.Consumable
Item.Usage.Ammunition

Item.Crafting.Craftable
Item.Crafting.Ingredient
Item.Crafting.RepairIngredient
Item.Crafting.UpgradeIngredient

Item.Property.Stackable
Item.Property.Tradeable
Item.Property.Droppable
Item.Property.Unique
Item.Property.Quest
```

- 위 속성 이름: 설계 용어
- 전체 GameplayTag 등록 완료를 의미하지 않음
- 제작 재료 종류명: Ingredient
- Unreal Material과 구분
- 대표 종류의 폴더 하나에 배치
- 부가적인 제작·거래·소모 기능은 속성으로 추가
- Consumable·Craftable 전용 종류 폴더 생성 없음
