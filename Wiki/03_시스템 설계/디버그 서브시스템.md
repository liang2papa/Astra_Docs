## 코드와 책임

- `Source/Astra_SoulLink/Utils/Debug/AstraDebugSubsystem.h/.cpp`
- `UAstraDebugSubsystem : UWorldSubsystem`. 별도 Tick 없음. 기능 실행 지점에서 해당 월드의 서비스를 호출한다.
- 콘솔 변수와 `astra.Debug` 명령은 위 cpp에만 등록한다. 설정 목록·범위·현재 값·사용처도 같은 등록부에서 조회한다.
- 실제 로그 포맷, 조준/파쿠르 도형, 원인 변경 시 출력, 0.1초 Pose/Montage 샘플, 0.25초 사선 차단 반복 억제는 서브시스템 소유다.
- 설정은 기존 콘솔 변수와 같이 프로세스 공통. 출력 제한·인스턴스 식별 상태는 월드별이며 Deinitialize에서 정리한다. FObjectKey/약한 참조는 게임 액터를 소유하지 않는다.
- Controller·Component·Handler에는 호출 지점만 남긴다. 내부 상태를 진단하기 위한 friend 접근은 NPCAIController·WeaponComponent·AttackSequenceHandler에만 허용하며 실행 상태를 변경하지 않는다.
- 로그 카테고리는 `LogAstraDebug`. 실제 오류·실행 실패 경고·소유 검사 checkf는 원래 기능 코드에 유지한다.

```text
Controller / Component / Handler 실행 지점
→ 해당 월드의 AstraDebugSubsystem
→ 중앙 설정 확인 → 액터별 중복/샘플 제한
→ LogAstraDebug 또는 화면 도형
```

## 하나의 진입 명령

```text
astra.Debug
astra.Debug list
astra.Debug NPC.Combat 1
astra.Debug NPC.Pose 1
astra.Debug Weapon.Aim 1
astra.Debug Weapon.AimAlpha 0.2
astra.Debug Weapon.Montage 2
astra.Debug off
```

인자 없는 `astra.Debug`와 `list`는 전체 키·현재 값·기존 콘솔 이름·허용 범위·사용처를 출력한다. 키는 대소문자를 구분하지 않는다. `<키> <값>`은 등록된 한 설정만 바꾼다. 잘못된 키·인자·범위는 설정을 변경하지 않는다.

`off`는 표시/로그 설정을 0으로 만든다. 투명도 값은 유지하고 실제 오류·소유 검사에는 영향을 주지 않는다. 활성화를 다시 원하면 원하는 키를 설정한다. 이미 그린 유한 수명 도형은 원래 수명이 끝날 때 사라진다.

## 진단과 게임플레이 경계

2026-10-25 당시 Projectile·Recoil 2개 키 추가로 9개. 10월 26일 Skill.Execution 추가 후 현재 10개. 기능 cpp에는 사건 호출만 유지, 콘솔 등록·로그 형식은 이 서브시스템 소유. 새 디버그는 기본 꺼짐이며 이번 변경의 빌드·실행 확인 전

```text
astra.Debug Weapon.Projectile 1
astra.Debug Weapon.Recoil 1
astra.Debug off
```

Projectile의 Hit→Deactivated는 Native 접촉 경로, LifetimeExpired→Deactivated는 탄 DA 수명, CurveEnd→Deactivated는 지형 충돌 없는 곡선 종료. Hit/회수 없이 EndPlayReason=0이면 외부 Destroy 경로 조사. Actor 제거 로그 없이 외형만 사라지면 Niagara 수명/Collision/Kill 모듈 확인. Profile=AstraProjectile·ProjectileResponse=0(Ignore)와 실제 HitActor/HitClass/HitComponent로 판정, 다른 Owner의 로그를 섞지 않음

- NPC의 높은 위치 공격→상실→추적 문제는 별도 이슈이며 이후 사용자 플레이에서 해결 확인. 명령/로그 정리 자체를 해결 증거로 사용하지 않는다.
- 발사/명중/탄약/쿨다운/취소, 추적 이동/Focus/Pitch, ABP 포즈 선택 정책은 이번 이전에서 변경하지 않는다.
- Pose의 `UpperActive=0`은 제공 그래프의 기본 로코모션 선택, `UpperActive=1/AimEnabled=0`은 무기 상체 유지+AO 목표 중립, `AimEnabled=1`의 실제 AimPitch로 조준각 유지 여부를 구분한다. ABP 값은 마지막 애니메이션 갱신 스냅샷이므로 연속 샘플로 판정한다.
- 새로운 디버그 옵션은 이 등록부와 서브시스템에 추가한다. 기능 cpp에 콘솔 문자열 검색·독립 CVar·DrawDebug 호출·진단 샘플 시계를 다시 추가하지 않는다.
