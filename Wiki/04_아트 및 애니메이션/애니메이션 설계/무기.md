## 에셋과 책임

기존 공통 경로: `Content/Astra/Entity/Humanoid/Animations/Unarmed/ABP_Unarmed.uasset`. 최신 제공 그래프: `/Game/CharacterAnimationSample/Shinbi/ABP_Astra_Player`. 각 Mesh의 실제 Anim Class에서 설정. Shinbi 경로를 모든 NPC의 공통 에셋으로 가정하지 않음

- EntityCharacter: 컴포넌트 준비 후 C++에서 AnimInstance 직접 초기화
- UAstraHumanoidAnimInstance: AnimationData와 이벤트 구독·해제·보간
- ABP_Unarmed AnimGraph: Main States·무기 포즈·UpperBody Slot·AimOffset·상하체 Blend
- WeaponComponent/CarryHandler: 활성 무기의 손·수납 부착과 현재 ABP의 ItemID별 Transform 적용
- 각 ABP 기본값: FireMontages·ReloadMontages·MantleMontage·DeathMontages와 WeaponAttachmentTransforms 설정
- WeaponDataAsset: 무기 메시·소켓·총열 시각 보정·Equip/Holster 설정. FireMontage·ReloadMontage·손/수납 Transform은 ABP로 이전, 미사용 DryFireMontage·DryFireSound 제거

무기 행동 애니메이션은 무기 Item의 소유물이 아닌 Humanoid Entity의 표현. 보스는 외형·추적 정책이 다르므로 일반 NPC ABP 상속을 필수로 두지 않음. Linked Anim Layer 확장은 미구현이며 WeaponAnimLayerClass 지정만으로 자동 전환되지 않음

## 초기화와 데이터 연결

### 부모·기존 변수 정리

1. 사용자 빌드 후 ABP Class Settings → Parent Class = AstraHumanoidAnimInstance
2. 기존 변수 사용처를 아래 AnimationData로 변경한 뒤 미사용 변수 정리. 같은 이름 변수의 자동 마이그레이션을 가정하지 않음
3. 기존 Event Blueprint Update Animation 계산은 사용자 연결 해제 상태 유지. 과거 EventGraph의 무기 매 프레임 조회를 다시 연결하지 않음
4. BlueprintInitializeAnimation과 BP Update에 초기화 체인 추가 없음. Entity C++ 초기화·엔진 재초기화 경로 사용

### 캐릭터 BP 초기화 제거와 ABP 기본값

1. 기존 ABP의 AimInterpSpeed 값을 기록한 뒤 Class Defaults → Animation | Tuning → Aim Pitch Interp Speed에 같은 값 입력
2. 캐릭터 BP의 Get Mesh → Get Anim Instance → Cast → InitABPClass 초기화 체인 제거. 해당 Cast의 다른 사용처가 있으면 그 연결 보존
3. ABP의 InitABPClass와 그 안의 InitializeForEntity 호출·참조 저장 제거. 기존 bIsInitialized 사용처는 상속 bAnimationDataInitialized로 교체
4. MovementComponent·WeaponComp·LocomotionComp·EntityCharacter 등 기존 BP 변수는 사용처 이전 후 미사용 항목만 제거
5. Class Defaults → Animation | Actions → Action Animations 확장
6. Fire Montages에 실제 WeaponData.WeaponType 키 추가. 예: Pistol·AssaultRifle. 해당 캐릭터 스켈레톤의 발사 몽타주 지정
7. Mantle Montage에 해당 캐릭터의 올라타기 몽타주 지정. 제공 Shinbi Task의 기존 값: `/Game/CharacterAnimationSample/Shinbi/Locomotion/LedgeClimb/MF_Astra_LedgeClimb_Up_Montage`
8. 발사 몽타주의 Weapon_FireCommit 유지. Mantle의 Root Motion·MantleTarget Motion Warping 설정 유지
9. ABP·캐릭터 BP·변경한 Task·StateTree Compile 후 실행 확인

Reload Montages에도 실제 WeaponType 키 추가 후 해당 캐릭터의 재장전 몽타주 지정. 기존 무기 DA의 ReloadMontage를 대체하는 설정. Montage의 UpperBody 슬롯 유지, 별도 재장전 AnimGraph 상태·새 Notify 추가 없음

Aim Pitch Interp Speed에 옮길 값은 기존 ABP의 AimInterpSpeed. 무기 DA의 Visual Aim Correction Interp Speed와 별도 항목. 후자는 무기별 총열 시각 보정 속도로 기존 WeaponDataAsset 위치 유지

```text
기존 Reload Task → GA → ExecuteReloadWeapon
→ 현재 ABP.ReloadMontages[WeaponType] 조회
├─ 설정 누락·재생 실패 → false → 기존 GA·Task 실패 종료
└─ 재생 성공
   ├─ 정상 종료 → 탄약 확정 → 기존 완료 결과
   └─ Sprint 취소·몽타주 중단 → 탄약 미확정 → 기존 실패·취소 종료
```

```text
Entity.InitClass → 컴포넌트 준비 → 현재 인간형 AnimInstance 연결(C++)
├─ 구성 오류 → Error 로그·초기화 실패 → 구성·순서 수정
└─ 성공 → 이벤트 구독·초기 스냅샷 → StateTree 시작
메시·ABP 재생성 → NativeInitializeAnimation에서 기존 Entity 재연결
종료 → Entity.EndPlay / NativeUninitializeAnimation에서 구독 해제
```

필수 참조 누락은 구성·초기화 순서에서 수정. 값 계산을 BP/C++ 양쪽에 중복 구현하지 않음

### Mantle Task 연결 변경

Execute Mantle 노드 Refresh 또는 재배치. Target=부모 Task의 EntityContext.LocomotionComp, 몽타주 입력 핀 제거

```text
ReceiveLatentEnterState
→ Bind Event to OnMantleFinished(이번 Task의 완료 이벤트)
→ PublishLocomotionState(TraversalEntered, Source=부모 Character)
→ ExecuteMantle()
  ├─ 목표점·ABP 설정·재생 실패 → OnMantleFinished(false)
  ├─ 정상 종료 → C++ 이동 복구 → OnMantleFinished(true)
  └─ 몽타주 중단 → C++ 이동 복구 → OnMantleFinished(false)

OnMantleFinished(bSucceeded)
→ Unbind Event from OnMantleFinished(같은 완료 이벤트)
→ FinishTask(bSucceeded)

ReceiveExitState
→ 남아 있는 이번 Task의 완료 이벤트 구독만 해제
```

기존 Tick의 IsMantleInProgress=false → SetMovementMode(Walking) → FinishTask(true) 체인 제거. 시작 실패·중단을 성공으로 덮는 경로 제거. 성공 Walking·실패 Falling 복구는 C++ 기존 책임. 사망·다른 전신 몽타주에 의한 중단도 동일 종료 경로. Task Exit의 이벤트 구독 해제는 이번 Task에 정리 책임이 있는 경우에만 추가

10/23 첨부 STT_PlayerMantle 확인: 완료 Custom Event 뒤 동일 OnMantleFinished를 Target=Self로 다시 호출하는 노드 존재. 자기 호출 노드 삭제 후 Custom Event → Unbind → FinishTask 연결 안내. bSucceeded 출력의 FinishTask 입력 연결은 정상. 실제 노드 수정·실행 결과 미확인

### AnimationData 핀 대응

상속 AnimationData Get → 핀 분할 또는 Break Astra Humanoid Animation Data. 초기화 여부는 bAnimationDataInitialized

Main States 내부 Locomotion·Jump/Fall/Land/Hanging도 대응 Getter 변경. 상태·전이 정책 자체 변경 없음

현재 C++ Pitch 제한 80도·FInterpTo 보간, AimYaw=0. 방향 제한은 기존 CharacterMovement.bOrientRotationToMovement 분기 사용. 카메라 View 제한과 AO 입력 범위는 별개. 과거 BP Pitch ±70도 계산 안내를 현재 계산 경로로 재연결하지 않음

## 소켓과 무기별 보정

활성 WeaponMesh는 현재 UStaticMeshComponent 하나. Static/Skeletal 무기 병용과 두 무기 동시 표시 기능은 현재 구현 범위 밖

| 위치 | 소켓·설정 | 기준 |
|---|---|---|
| 캐릭터 오른손 | WeaponSocket_R | 권총·라이플 공용 기준점. 무기마다 공용 소켓을 옮기지 않음 |
| 캐릭터 오른쪽 허벅지 | PistolHolsterSocket | 권총 수납 |
| 캐릭터 등 | 실제 등 수납 소켓명 | RifleHolsterSocket은 초기 제안명. 저장된 WeaponHolsterSocket 등을 사용했다면 그 이름 지정 |
| 무기 메시 총구 | Muzzle | 실제 총구 위치. 캐릭터 Skeleton 소켓과 구분 |
| 무기 메시 왼손 | LeftHandGrip | 별도 절차적 IK가 필요할 때의 접촉 목표. 최근 AO 꺾임의 원인에서 제외 |
| 무기 메시 확장 | ShellEject / AimPoint | 탄피·정밀 정렬 기능 추가 시 후보, 현재 필수 아님 |

등 소켓은 척추 뼈에 추가. spine_03은 시작 후보이며 실제 위치에서 결정. Preview Asset은 위치 확인용일 뿐 게임 부착을 대신하지 않음. 별도 BP Attach 노드를 추가하지 않음

### WeaponDataAsset 설정

| 필드 | 권총·라이플 적용 기준 |
|---|---|
| WeaponType / WeaponStaticMesh | Pistol 또는 AssaultRifle / 실제 준비된 메시 |
| AttachSocketName | WeaponSocket_R |
| HolsterSocketName | 권총 PistolHolsterSocket / 라이플 실제 등 소켓명 |
| MuzzleSocketName | 메시의 실제 총구 소켓명 |
| EquipMontage | None. 꺼내기 모션 불필요 |
| DrawReadyDelay | 기존 설정 유지. 모션 생략과 지연시간 변경은 별개 |
| HolsterMontage | 기존 무기별 정책. 권총 값을 라이플로 무조건 복사하지 않음 |

### ABP의 무기 모델별 부착 Transform

1. 빌드·에디터 재시작 전 기존 무기 DA의 EquippedMeshTransform·HolsteredMeshTransform 값 기록
2. 각 캐릭터 ABP → Class Defaults → Animation | Weapon Attachment → Weapon Attachment Transforms에 항목 추가
3. Key는 무기 DA의 Item | Identity → ItemID와 동일한 Name. Pistol·AssaultRifle 같은 WeaponType을 대신 입력하지 않음
4. Value의 Equipped Mesh Transform에 손 소켓 기준 위치·회전·크기 지정
5. Holstered Mesh Transform에 홀스터 소켓 기준 위치·회전·크기 지정
6. 같은 무기라도 각 캐릭터 ABP에서 자기 체형에 맞게 조정. 같은 종류의 다른 모델은 각각 ItemID 항목 추가
7. 항등 Transform이 맞는 무기도 항목 등록. None·없는 키는 Error 로그와 부착 실패

SocketName·무기 메시·Muzzle 소켓은 무기 DA 기존 위치 유지. BP WeaponMesh 기본 Transform은 런타임 부착으로 덮일 수 있으므로 보정값은 위 ABP 항목에 저장. 소켓과 Transform 양쪽에 같은 오프셋 중복 적용 없음. 숫자는 실제 모델 원점·크기에서 결정

```text
무기 최초 연결·교체 → 새 WeaponData.ItemID로 현재 ABP 설정 검사
├─ 누락 → Error·연결 실패, 기존 무기 실행 취소 없음
└─ 존재 → 기존 실행 취소 → 손 유지 또는 홀스터 소켓 부착
   → 대응 상대 Transform 적용 → 기존 Carry 상태·알림 처리

Draw·Holster → 현재 무기 ItemID 설정 조회 → 대응 소켓·Transform 적용
├─ 실패 → 기존 Draw·Holster 실패·정리 경로
└─ 성공 → 실제 부착 상태 변경 알림
취소 → 기존 실행 Delegate·Timer 정리, 새 부착 성공 알림 생성 없음
```

사망 설정은 같은 ABP의 Animation | Actions → Action Animations → Death Montages 배열. 연결·실패·중단·제거는 [공통 사망 연결](../../07_QA_테스트/공통%20사망%20GA·몽타주·제거%20연결.md) 기준

발사·재장전 몽타주는 WeaponDataAsset 대신 ABP.ActionAnimations의 FireMontages·ReloadMontages에서 WeaponType으로 선택. DryFire 설정은 사용자 요청으로 제거

EquipMontage=None도 Draw 몸 정렬·손 부착·DrawReadyDelay·Ready 경로 유지. Holster 모션 생략으로 확대하지 않음. Holster 역재생은 코드 강제가 아닌 Montage 에셋에서 설정

## 보스 ABP 구성 착수 — 2026-10-24

최신 사용자 지정 다음 작업. 일반 NPC의 발사 몽타주·추적 상체 문제는 사용자 해결 확인, 보스 ABP와 구분한다. 이번 착수는 에셋/입력과 연결 순서 정리이며 C++·uasset 변경이나 Editor Compile·PIE 수행을 뜻하지 않는다.

확인된 기존 에셋:

- `/Game/Astra/Entity/Boss/ABP_Boss`
- `/Game/Astra/Entity/Boss/Animation/Boss_Idle`
- `/Game/Astra/Entity/Boss/Animation/Locomotion/BS_Astra_Boss_Walk`와 전진/후진/좌/우 걷기 클립
- `/Game/Astra/Entity/Boss/Animation/Boss_Fire_Montage`
- `/Game/Astra/Entity/Boss/Animation/Locomotion/Boss_Death_Front_01_Montage`, `Boss_Death_Front_02_Montage`, `Boss_Death_Back_01_Montage`

사용자 확인: **ABP_Boss의 그래프는 비어 있으며 처음부터 구성한다.** 실제 Skeleton 호환·Slot·Notify·Class Defaults의 값은 별도 확인 대상이다. Boss 하위에는 과거 Idle_Walk_Run/Jog 후보도 존재하지만 사용자 의도는 **걷기 4방향, 달리기 없음**이므로 기본 제작은 BS_Astra_Boss_Walk 기준으로 진행한다.

1. ABP_Boss의 Parent Class가 AstraHumanoidAnimInstance인지와 실제 보스 Mesh/Skeleton 호환 확인. 공통 C++ InitializeForEntity를 재사용하고 EventGraph에 이동값·조준값 중복 갱신을 새로 만들지 않음.
2. 1차 로코모션: Boss_Idle Sequence Player는 Loop 활성화. Blend Space Player의 Direction 축에 AnimationData.Direction, Speed 축에 AnimationData.GroundSpeed 연결. Blend Poses by Bool은 bShouldMove=True에 Walk, False에 Boss_Idle. 결과를 BossLocomotion 캐시에 저장. 축 이름·배치는 실제 BlendSpace 설정 확인, Direction -180~180, Speed 상한은 실제 걷기 속도와 클립 기준으로 지정(수치 미정). 플레이어를 바라보는 이동이므로 Orient Rotation to Movement는 사용하지 않는 기존 NPC 정책 확인. native Direction은 해당 옵션이 켜져 있으면 제한되므로 함께 확인.
3. 발사 설정: Class Defaults → Action Animations → Fire Montages의 GrenadeLauncher 키에 Boss_Fire_Montage 등록. 실제 Skeleton의 UpperBody Slot과 몽타주 Track 이름 일치, Montage Notify Weapon_FireCommit 확인. 발사를 위한 별도 Montage Play EventGraph 추가 없음.

- 플레이어는 Controller Yaw + 보정값. NPC는 Focus 타겟 방향 + 보정값, 공격 전 방향 검사도 같은 기준
- NPC의 Focus Actor가 없는 이동 방향 회전은 기존 처리 유지. Actor Yaw에 보정값을 반복 누적하는 Blueprint 추가 금지
- 가까운 표적의 시차·상하 조준 오차는 별도 확인 대상. 카메라·ControlRotation·무기 상대 Transform의 동시 보정 없음

```text
손 부착 → 현재 무기 WeaponType → 현재 ABP의 Yaw 보정 조회
├─ 종류 미등록 → 0도
└─ 등록 → Controller/타겟 방향 + 보정값 → 기존 몸 회전 경로
무기 교체 → 새 무기 종류 재조회
수납·해제·사망 → 보정 0도
Draw/Holster 취소 → 실제 손 부착 여부 기준, 별도 역회전 없음
필수 ABP 부모·무기 데이터 누락 → Error 로그와 보정 미적용
```

### 머리 기본 자세의 소폭 보정 — 사용자 ABP 연결

얼굴의 조준점 추적 없이 머리를 조금 드는 고정 자세 보정. C++ 머리 회전 설정 추가 없음

10/23 사용자 머리 들기 처리 완료 확인. 총기의 상하 정렬 해결 완료와 별개

```text
AO를 포함한 캐시 입력 포즈
→ Local To Component
→ Transform (Modify) Bone
→ Component To Local
→ 기존 Save Cached Pose
```

- 대상은 실제 스켈레톤의 머리 본, head가 존재하면 head 선택
- Rotation Mode: Add to Existing. Rotation Space: Bone Space
- Translation Mode·Scale Mode: Ignore
- Rotation 핀 노출 후 ABP의 Rotator 변수 HeadPoseOffset 연결. 작은 각도부터 프리뷰 조정, 본 로컬 축 기준 실제 머리 상승 방향 확인
- Alpha 핀은 Float 형식. AnimationData.bWeaponUpperBodyActive AND NOT AnimationData.bIsDead → Select Float의 Pick A 연결, A=1·B=0
- 무기 상체 활성 중 보정, 비무장·사망 중 비활성. 수납 중 적용 여부는 기존 실제 손 부착 기반 상체 활성 기준
- 이미 Component Space인 구간에 삽입할 경우 중복 공간 변환 생략. Save Cached Pose 입력은 Local Space로 복귀
- 보정 뒤 머리를 덮어쓰는 다른 노드가 있으면 그 최종 머리 수정 뒤·FullBody 사망 슬롯 앞에서 적용. 머리 전용 Look At·조준점 방향 계산 없음

### 10/23 확인 결과와 상하 조준 후속 검토

- 기본 자세에서 총기 좌우 정렬 정상 사용자 확인
- 위·아래 조준 시 총기 정렬 틀어짐 잔존. 머리 들기 완료와 별도 잔여
- 후속 방향: 총기의 위치·회전 조정 검토. 기본 자세의 좌우 정렬 보존 조건
- 기존 ABP의 무기별 부착 설정 활용 여부 검토. 고정 Transform 조정·조준 Pitch 연동 등 실제 적용 방식 미정, 신규 보정 구현 승인·완료와 구분
- 조준점과 총열의 완벽한 일치 요구 없음. 눈에 띄는 상하 조준 오차 완화와 자연스러운 표현 기준
- 확인 범위는 사용자 보고의 기본 자세·머리 처리. 전체 무기·캐릭터 조합의 성공으로 확대 없음

### 몸·팔·무기 정렬 순서와 공개 구현 비교

1. ABP의 ItemID별 EquippedMeshTransform으로 손바닥·손잡이 기준 위치·회전·크기 확인. 조준 중 무기 메시만 목표 방향으로 재회전하는 경로 추가 없음
2. 몸 Yaw는 기존 Controller·NPC 타겟 방향에 ABP의 무기 자세별 고정 보정 적용. 무기 활성 시 bUseControllerRotationYaw=true 경로 유지
3. 상하 조준은 올바른 Mesh Space Additive AimOffset과 Base Pose로 상체·팔·손을 함께 표현. 총구 오차를 AO 뒤 척추에 다시 누적하지 않음
4. 기본 포즈가 맞은 뒤 체형 차이로 손 접촉이 남는 경우에만 Two Bone IK·Hand IK Retargeting 검토. 과거 해결된 불필요 FABRIK 일괄 복구 없음
5. 왼손 목표는 무기 LeftHandGrip을 해당 IK가 요구하는 좌표로 변환. 오른손의 무기 부모 관계와 IK 목표 사이 순환 의존 방지

```text
기본 로코모션·무기 자세 → UpperBody Slot → 무기 AimOffset
→ 기존 상하체 합성 → 필요한 경우의 손 접촉 IK
→ 기존 최종 FullBody Slot → Output

사망·수납·비무장 → 무기 상체·손 접촉 보정 비활성
발사·재장전 중단 → 기존 실행부 정리, 무기 Transform 임의 재회전 없음
```

- 로컬 LyraGameplayAbility_RangedWeapon.cpp의 GetTargetingTransform: 카메라 레이 시작점을 Pawn 쪽으로 전진. Astra는 몸과 실제 Muzzle 깊이를 함께 사용
- [Lyra 애니메이션](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-in-lyra-sample-game-in-unreal-engine): Actor의 Controller Yaw 추종·RootYawOffset·무기별 조준 레이어
- [Fortnite 공개 레이어 사례](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-blueprint-linking-in-unreal-engine): 공통 로코모션과 무기 상체 표현 분리. 특정 게임의 모든 조준·탄도 내부 구현으로 확대 해석하지 않음
- [AimOffset](https://dev.epicgames.com/documentation/en-us/unreal-engine/aim-offset-in-unreal-engine)·[Hand IK Retargeting](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-blueprint-hand-ik-retargeting-in-unreal-engine): 상체 자세와 체형별 손 접촉의 별도 책임

기존 ANIM-002는 Idle/Fire 포즈·루프 단절 해결 기록 유지. Montage Blend In/Out·무기 대기 포즈·수납 부착 Notify 시점 확인, 값 변경은 실제 재현 기준. 상세 과거 사례는 [애니메이션 이슈 가이드](../../08_기술%20위키_공통%20가이드/Troubleshooting/Astra%20애니메이션%20이슈%20가이드.md) 참조

## 교체·실패·취소 전체 흐름

```text
기존 손 부착 A → 유효 무기 B 선택
→ A의 Fire/Reload/Draw/Holster·예약 행동·런타임 정리
→ B의 데이터·메시·총구·손/수납 소켓·현재 ABP ItemID 설정 검사
├─ 실패 → 기존 Bind 실패·Clear 경로 → 비무장 기본 포즈
└─ 성공
   ├─ A가 손 부착 → B 손 소켓·ABP의 B ItemID EquippedMeshTransform → Ready
   │  → Draw 재요청 생략
   └─ 최초/비무장 → 기존 수납 기준 연결 → Draw 몸 정렬
      → Equip Montage 없음 → 손 부착
         ├─ 실패 → Draw 실패·예약 행동 해제, 발사 없음
         └─ 성공 → DrawReadyDelay → Ready
   → 장착·Carry·실제 부착 이벤트가 dirty 표시
   → 다음 NativeUpdateAnimation의 AnimationData → 새 무기 포즈

수납 완료 → 활성 무기 수납 소켓·ABP의 현재 ItemID HolsteredMeshTransform → 상체 무기 포즈 비활성
해제/빈 슬롯 → 비무장 정리 → FinalBasePose
취소/교체 → 이전 지연 Callback·Notify·Task Exit가 새 무기 실행에 간섭하지 않도록 정리
종료/재초기화 → 이전 Delegate 해제
```

교체 직후 손 부착 유지와 자동 수납 정책 제거는 별개. Player는 기존 AutoHolsterDelay 유지, NPC Idle은 기존 무기 활동 갱신 정책 사용
